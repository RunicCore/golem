# Changelog

This file is the complete list of changes. The documentation site's
[release notes](docs/changelog.md) summarize the release.

## 1.1.0

Golem 1.1.0 is the first stable release. It brings TypeScript models, NestJS controller contracts and an OpenAPI to TypeScript SDK into one generation workflow. It has four independently installable packages:

| Package | Purpose |
| --- | --- |
| `@exprtlabs/golem-model` | Generate model bases from TypeScript declarations |
| `@exprtlabs/golem-openapi-ts` | Generate typed clients and runtime models from OpenAPI |
| `@exprtlabs/golem-ts-openapi` | Generate OpenAPI from NestJS controllers |
| `@exprtlabs/golem` | Shared CLI, model runtime, validation and serialization |

**Breaking** marks a change against 1.1.0-rc.0, the pre-release.

### Models

- **Breaking:** a tag inside a hole of a template literal type, such as `` `id-${string & MinLength<3>}` ``, stops generation with [`RUNM1045`](docs/reference/diagnostics.md#runm1045). Before, golem dropped the tag without a message and read the field as a plain `string`. Write the tag beside the type instead: `` `id-${string}` & MinLength<3> ``.
- The generated validators file no longer starts with `// @ts-nocheck`, so `tsc` checks it. A project with `noUnusedLocals` or `noUnusedParameters` accepts it: a parameter that a validator never reads starts with `_`, and a local that nothing reads is not declared. Generation now type-checks the validators module too and stops on an error in it, so a module that imports `@exprtlabs/golem` must lie where that package resolves, as in a build with `tsc`.
- An option typed with `undefined`, such as `{ exact?: false }` or `{ validation?: 'sanity' }`, reads as its literal. Before, `exact?: false` read as not set, so the default `exact: true` applied, and `validation?: 'sanity'` stopped with [`RUNM1089`](docs/reference/diagnostics.md#runm1089). **Breaking:** an `exact` or `allowAny` option typed as a wide `boolean` now stops with `RUNM1089`. Before, it read as not set and the default applied.
- `stringify` and `toWireFormat` of a model write the value of a field that holds a golem-mode SDK type tagged with `TSerde` through that serde, as the decode reads it. Before, they wrote the SDK type itself, so `toWireFormat` failed its wire check. A model whose child is declared in another file with `{ validation: false }` and holds a `Date` builds and stringifies. Before, the build stopped with a missing export.
- **Breaking:** a variant of a `Discriminator` union that has a `TSerde` whose wire form is not an object, such as a string, stops generation with [`RUNM1082`](docs/reference/diagnostics.md#runm1082) and names the variant. A string holds no tag, so golem cannot dispatch it. Before, the generated code failed to compile, or a validation-off read treated the string as an object. A `TSerde` that writes an object with the tag still works.
- A model that sets `{ validation: false }` generates for a callable field, a constructible type and an unsupported type, such as `symbol`, also in a job with validation on. Before, `RUNM1003` or `RUNM1004` stopped it, because only the setting of the job counted.
- **Breaking:** the `ModelValidator` constructor takes its mode as a required option, `new ModelValidator(model, { cache: 'attach' })`. Before, the second argument was a positional `cache = true`; `{ cache: 'defer' }` replaces `false`. The `ModelValidator` of `@exprtlabs/golem-openapi-ts` still takes the model only.
- `strip: true` in the options of `parse`, `fromWireFormat`, `stringify` and `toWireFormat` removes the keys that a closed object does not declare, at every level and every validation level, before the checks run. The result holds the declared keys only, also for a class. A `Record`, an `AdditionalProperties` tag, pattern properties and an object with `exact: false` keep their extra keys. Types: `DecodeOptions` and `EncodeOptions` from `@exprtlabs/golem/serde`. An encode strips the plain objects of the model value, also those that a class instance holds in its declared fields, which lets a handler return a database row, or a class that holds one, with an extra column. The value of a `TSerde` field stays as it is. The default is unchanged. See [`strip`](docs/reference/runtime-api.md#strip).
- A field typed as an intersection of several data parts and a tag, such as `{ a: string } & { b: number } & MinProperties<1>`, keeps every part. Before, only the first part stayed, so a declared field disappeared and valid data failed. A brand beside `string` works in either order.
- A generic tag alias with a compound base, such as `type NonEmpty<T> = T[] & MinItems<1>`, generates. Before, it stopped with `RUNM1003`.
- `Record<number, V>` and `{ [id: number]: V }` convert their values as a string-keyed record does, and reject a key that is no number. Before, they rejected valid data.
- Models whose names differ only in a character that a short name drops, such as `A$` and `A_`, each get their own codec. Before, generation stopped with an unresolved reference.
- `validateInstance` and `ModelValidator.validate` honor `maxDepth`. A function in `.messages()` runs once for each issue.
- A `Date` field reads a leap second, such as `2026-10-06T23:59:60Z`, as second 59, as `Temporal.Instant` does. `Temporal.Instant` reads a fraction of more than nine digits and keeps nine.
- A `UniqueItems` check takes one pass, so a list of any length validates in linear time. It reports the same `unique` issue and `indexes`. Before, the check compared every pair, so one long list could hold the event loop.
- A generated `IModel` constructor writes each field at its own site, so `fromWireFormat` and `new` of a class model run about 1.8 to 1.9 times faster. A field name that the object already reaches, such as an accessor of a subclass, still becomes an own data property, and its setter does not run.
- A model that reaches a recursive model checks `maxDepth` with a walk that allocates no set or map for each node, and `validate` runs about three times faster on a recursive model. The limit and the errors stay the same.
- A `Date` field now needs an RFC 3339 `date-time` text with an offset, such as `2025-01-02T03:04:05Z`, at every validation level, validation off included. Before, with validation off, texts such as `5`, `2025-01-02` and a time with no offset were read as a date. A Temporal field likewise accepts only its wire form: `20250102` is no longer a `TemporalPlainDate`, and `p1d` is no longer a `TemporalDuration`. A text that does not fit throws `Deserialization` with `causedByInput: true`. The write side follows: `stringify` and `toWireFormat` throw `Serialization` for a value outside the wire form. Before, with validation off, golem wrote such text, such as `2025-01-02[u-ca=gregory]`.
- A `TSerde` deserializer that throws while golem reads wire input now makes `parse`, `fromWireFormat` and the Nest interceptor throw `LibError` with `causedByInput: true`, in a field, an array item, a record value and a union branch. `NestModelInterceptor` answers HTTP 400 for it. Before, `causedByInput` was `false` and the interceptor answered 500. The exception of a serializer that throws reaches the caller unchanged.
- `Date` and the Temporal classes are built-in `TSerde` types. Golem supplies a default pair of functions for each, and no mechanism of their own remains. A field typed `Date`, `Temporal.Instant`, `Temporal.ZonedDateTime`, `Temporal.PlainDate`, `Temporal.PlainDateTime`, `Temporal.PlainTime` or `Temporal.Duration` converts with no tag, and a plain Temporal field checks the JSON form of its class as the matching `TemporalX` type does. A `TSerde` tag on the type replaces the default. See [Dates and times](docs/guide/field-types.md#dates-and-times).
- The model value of a `Date` or Temporal field is checked with `instanceof`, as the class of a `TSerde` field is. A value that fails reports one issue with code `instance`, `model` holding the class name, such as `Expected an instance of Date`. An invalid `Date`, such as `new Date(NaN)`, fails too. Before, a `Date` field reported code `type` with `expected: ['Date']`, and that entry of `expected` is gone. A `TSerde` class that a `*.model.ts` file declares now stops generation with [`RUNM1065`](docs/reference/diagnostics.md#runm1065), as a `TSerde` function does. A type with no run-time class, such as an `interface`, has no instance check. The `VALIDATE_UNSUPPORTED_KEYWORD` message for a malformed class check names `golemModelClass`, where it named `golemModelDate` for a `Date`.
- A `TSerde` field whose JSON value is a string, a number or a boolean reads only that JSON type, at every validation level. Before, with validation off, another JSON value such as `5` for a string skipped the decoder and became the model value. Now it throws `Deserialization` with `causedByInput: true`. A `Date` field also reads only a `date-time` string: `fromWireFormat` no longer accepts a `Date` instance there, such as a database row, with validation off as well as on.
- [`RUNM1052`](docs/reference/diagnostics.md#runm1052) and [`RUNM1085`](docs/reference/diagnostics.md#runm1085) name a Temporal class too, such as `IModel<Temporal.Instant>` and `Temporal.Instant & Model`.
- A `date-time` union that golem cannot convert, such as a `oneOf` of a `date-time` string and a plain `string`, stops with one message for both `dates` values: `A date-time model union must have one Date or Temporal branch and optional null. Ambiguous string branches cannot be converted to Date or Temporal.` Before, the message named `Date` or `Temporal` by the `dates` value.
- `encodeGeneratedModel` and `decodeGeneratedModel` are deleted. Use `toWireFormat<T>` and `fromWireFormat<T>`. `toWireFormat` validates the model when its profile does and takes `{ validate: false }`. A generated model file has no class-level encoder, and the `encode<Name>` function of a `golem-openapi-ts` model is `toWireFormat<Name>` under a second name.
- A field typed `Date & Model`, `bigint & Model`, or `{ x: Date } & { x: Model }` stops generation with [`RUNM1085`](docs/reference/diagnostics.md#runm1085), with validation on and off. Before, a `Date` field generated a field of `Date`'s method names with validation off and `RUNM1004` blamed `toString` with validation on, and a `bigint` field stopped with an uncoded `TypeError`. A `Date` with a phantom brand, such as `Date & { readonly __brand: 'Timestamp' }`, is a `Date` field, as a branded string or number already was.
- A field typed `Date | Date[]` or `Date | string[]` generates and converts by its wire value: a string is the Date, an array is the array. Before, it stopped with [`RUNM1082`](docs/reference/diagnostics.md#runm1082). A nullable form such as `Date | Date[] | null` keeps `null`.
- A type alias that refers to itself now works in any shape: a union, an array, a tuple or a record. `type JsonValue = null | boolean | number | string | JsonValue[] | { [key: string]: JsonValue }` is a valid field type. Golem generates one function for the alias. [`RUNM1003`](docs/reference/diagnostics.md#runm1003) no longer reports a recursive alias, and [`RUNM1056`](docs/reference/diagnostics.md#runm1056) now means a cycle that golem cannot name.
- A `TSerde` whose wire type is a recursive model, such as `decode(wire: TNode)` with `type TNode = IObject<{ next?: TNode }>`, generates with validation on and off. Before, generation stopped with the TypeError `Unresolved schema reference` (validation on) or the internal error that the code names a helper the file does not place (validation off).
- A recursive interface or class, such as `interface Tree { kids: Tree[] }`, now generates one schema that refers to itself through `$ref`. Before, generation stopped with a stack overflow. Copies with the same shape, such as one `Node` in two files, share one projection and the plain name. Different shapes, such as `Page<string>` beside `Page<number>`, give the one read second a longer name (`PageNumber`). [`RUNM1059`](docs/reference/diagnostics.md#runm1059) now covers inline types only.
- The longer name of a recursive generic type whose type arguments hold a union, such as `PageEastWest` for `Page<'east' | 'west'>` or `PageRecordEastWestNumber` for `Page<Record<'east' | 'west', number>>`, lists the members of the union in sorted order, and so does the number of a union variant that no written type names. Before, both followed the order in which TypeScript printed the union, so on TypeScript 6 a name could change with the order in which the checker met the literals. A union with `string`, `number`, `null` or `undefined` keeps their places.
- A type that holds `Partial`, `Required`, `Pick` or another mapped type of itself, such as `interface Cfg { patch?: Partial<Cfg> }`, now generates one schema that refers to itself through `$ref`. Before, generation stopped with a stack overflow. A generic type that expands without end, such as `interface Box<T> { next?: Box<Box<T>> }`, stops with [`RUNM1083`](docs/reference/diagnostics.md#runm1083).
- A union of scalars, one array and one object converts and validates without a tag.
- `ModelInit` accepts a value of a type that holds itself through an array, such as `JsonValue`, and no longer stops the compiler with "Type instantiation is excessively deep". A tuple keeps its exact shape.
- `golem-ts-openapi` writes a controller response that has a recursive alias type as one component that refers to itself.
- `golem-openapi-ts` generates a component schema that refers to itself through `$ref`, also when it is not an object, instead of stopping with an error. A model field of it has the type `Types.<Name>`. See [Recursive schemas](docs/reference/openapi-support.md#recursive-schemas).
- A model over a mapped, conditional or `Pick` type keeps the `TSerde` conversion of a field. Before, the field lost it.
- `parse`, `fromWireFormat` and the class-level decode reject a class-model field, array item or record value that is not an object with "<Name>BaseModel expected an object.", an input error at the field's path. Before, with validation off, `'text'` or an array item `5` became an empty model and `null` failed with a plain TypeError that was not marked as caused by input.
- A registered codec holds no JSON Schema. `ObjectCodec` and `ObjectCodecImpl` lose `schema`, `wireSchema`, `modelOnlySchema`, `wireOnlySchema` and `schemaRefsResolved`, and `@exprtlabs/golem/serde` no longer exports `resolveGeneratedModelSchemaRefs`. A generated model file carries no schema text, so it is smaller and loads without parsing one. `objectCodecValidationReference` returns the codec id for `model` and `Id#plane` for every other plane, `Id#wire` included, also when the wire schema equals the model schema; a generated parse asks a validation context for that key. The OpenAPI document and the validators come from the build, not from a registered codec. `NestModelInterceptor` decodes query strings from the table of the fields that need decoding, which the nest extension of `golem-ts-openapi` writes into the `data` of the codec (the hook `model.codecData`). Core has no `queryFields` on a codec, and `@exprtlabs/golem/serde` no longer exports `QueryFieldShape` and `QueryFieldTable`. A project without `extensions: { nest: {} }` gets no table.
- A model union of two or more object types, models or SDK types declares its tag key with the `Discriminator` tag from `@exprtlabs/golem/tags`, such as `value: (TEmail | TPhone) & Discriminator<'kind'>`. Golem reads only that key; it no longer looks for a literal property that the variants share. A union without the tag stops with [`RUNM1080`](docs/reference/diagnostics.md#runm1080) at every position and with validation on and off, also when no variant needs conversion. Each object variant declares the key as a required literal with a value of its own, or generation stops with [`RUNM1087`](docs/reference/diagnostics.md#runm1087). The tag on anything other than such a union stops with [`RUNM1051`](docs/reference/diagnostics.md#runm1051). The tag does not change the application type. See [Unions](docs/guide/field-types.md#unions).
- `Discriminator<'kind', TMoney>` names a default variant, the one variant that has no tag, such as an SDK type beside tagged objects. An object whose tag matches no variant decodes as the default.
- A declared default that is not an object, such as `Discriminator<'kind', Date>`, stops generation with [`RUNM1051`](docs/reference/diagnostics.md#runm1051). A scalar, array or `null` variant needs no default: golem picks it by its JSON type.
- An open declared default, such as an SDK type that allows extra keys, takes neither a value that carries another variant's tag nor a model instance of another variant's class. Before, `validateInstance` and the model check accepted such a value as the default.
- `stringify` and `toWireFormat` tell a model instance of a tagged union by its class first: a tag-less `Email` instance is written as the `Email` variant with its tag, and an instance whose tag names another variant throws. Before, the default variant wrote it and dropped its fields.
- Strings, numbers, booleans, literals, one array or tuple, and `null` can sit beside the tagged objects of a union, as in `((string | TEmail | TPhone) & Discriminator<'kind'>) | null`. Golem picks a value by its JSON type first, then an object by its tag, then the default.
- A `TSerde` class value whose JSON form is a scalar, such as `URL & TSerde<typeof encodeUrl, typeof decodeUrl>` with a string wire, can sit beside the tagged objects of a union, as in `(Link | TEmail | TPhone) & Discriminator<'kind'>` or `Link | ((TEmail | TPhone) & Discriminator<'kind'>)`. It writes, reads and validates with validation on and off. An object beside the class value goes to its own variant: a model instance or a plain object is a tagged variant, and any other object goes to the serializer of the class value. Before, generation stopped with [`RUNM1082`](docs/reference/diagnostics.md#runm1082). A `TSerde` value written as an object or an array beside tagged objects still stops with `RUNM1082`.
- The generated names of the variants of a tagged union come from the values of the declared key. Before, they came from the first literal property that the variants shared; names stay the same where that was the same key.
- Any other union that golem cannot convert without trying its variants stops generation with [`RUNM1082`](docs/reference/diagnostics.md#runm1082). The message names the model file and lists the variants. Before, the message had no code and no file.
- A syntax error in a model source, such as a half-typed field, stops generation with the compiler's own error and its file and line. Before, it was reported as [`RUNM1011`](docs/reference/diagnostics.md#runm1011).
- [`RUNM1053`](docs/reference/diagnostics.md#runm1053) points at the inline `IObject` or `IModel` definition that it rejects, such as one variant of a union, and shows its text. [`RUNM1058`](docs/reference/diagnostics.md#runm1058) from the controllers job adds the first TypeScript error at its position, such as `TS2304: Cannot find name 'strin'`, so a broken model gives the same cause when the watch starts and after an edit.
- `fromWireFormat` of a cyclic value with validation on throws a `LibError` of kind `deserialization`, not a stack overflow.
- On the first `golem generate`, a utility type over a class of your app resolves its fields. This holds for an inline mapped type such as `{ [K in keyof Customer]: Customer[K] }`, a utility type that you wrote, `Partial<Pick<Customer, 'name'>>` and an indexed access. Before, these stopped with [`RUNM1058`](docs/reference/diagnostics.md#runm1058) or gave unknown fields until the second run.
- A model defined by a mapped type over its own class still stops with [`RUNM1058`](docs/reference/diagnostics.md#runm1058). The message now names the model and the class, and tells you to declare the fields in the model.
- A tagged field that you reach through `Pick` keeps its validation tag on every run. Before, the second run dropped the tag.
- `TValidation` and `TSerde` accept functions that you declare as typed consts, such as `export const check: (v: string) => boolean = ...`. A nullable union member that you write through a tag alias, such as `Inner<5> & string | null`, now stops generation with [`RUNM1064`](docs/reference/diagnostics.md#runm1064). Before, it generated a validator that rejected every plain string.
- An `IModel` or `IObject` whose fields type is not an object type, such as `IModel<string[]>`, `IObject<Date[]>` or `IModel<string>`, or is a type that a `TSerde` converts as a whole, stops generation with [`RUNM1052`](docs/reference/diagnostics.md#runm1052), and the message names what it found. Before, an array root wrote an invalid model file or stopped with a wrong [`RUNM1004`](docs/reference/diagnostics.md#runm1004), and a whole-object `TSerde` root wrote a file that did not compile. A root union keeps the same code. A fields type that does not resolve, such as a missing import, stops with [`RUNM1058`](docs/reference/diagnostics.md#runm1058).
- A property with a symbol key, such as `[sym]: string`, in a model, in a nested object of a model or in the type of a controller parameter stops generation with [`RUNM1070`](docs/reference/diagnostics.md#runm1070). Before, a model wrote a field named `__@sym@4`, and a parameter became a query or header parameter with that name.
- Validation of an object type with no named properties is faster, and `stringify` of a map of numbers, such as `{ [key: string]: number }`, is faster. The results are the same.
- A `MultipleOf` check with a decimal divisor such as `MultipleOf<0.1>` is faster. Every value gets the same result.

- A model `number` field can carry `Format<'int32'>`, `Format<'int64'>`, `Format<'float'>` or `Format<'double'>`. Its schema gets the `format`, and the generated validator rejects a value out of range, such as `2**31` for `int32` or `Infinity` for `double`.
- Model output built with validation off no longer carries validation bindings in its generated wire schema.
- [`RUNM1004`](docs/reference/diagnostics.md#runm1004) for a model `Map` or `Set` field names `Map` or `Set`. Before, it named one of their methods.
- A derived model that narrows an array-of-models field, such as `IModel<TOwner & { pets: TCat[] }>` where `TOwner` has `pets: TPet[]`, decodes the items as `TCat` model instances. Before, the items stayed plain objects.
- A `TSerde` whose wire type is a `number` or a `boolean` runs its deserializer when golem decodes the field. Before, `parse` and `fromWireFormat` returned the wire value unchanged.
- The generated code of a tagged model union holds its class-and-tag dispatch once, as one module-level selector per direction that every writer and reader of the file shares. Generated files with tagged unions are about a fifth to two fifths smaller.
- `stringify` and `toWireFormat` write a `Date` beside the objects of a union as its ISO string, as in `(TEmail | TPhone | Date) & Discriminator<'kind'>` or `TEmail | Date | string[]`. Before, the tagged form threw `Unknown kind discriminator value` and the untagged form kept the `Date` object.
- A model that reaches a recursive model rejects input nested deeper than `maxDepth` (512 levels of objects and arrays by default) with a `LibError` of kind `deserialization` and `causedByInput` on `parse`, `fromWireFormat` and `assert`; `validate` answers `false`. `NestModelInterceptor` answers HTTP 400 and takes `maxDepth` as an option. Before, a deeply nested body overflowed the stack and answered 500. A model that reaches no recursive model is not walked. See [maxDepth](docs/reference/runtime-api.md).
- A union of a `TSerde` scalar and `null`, also beside a tagged union, decodes `null` as `null`. Before, the deserializer ran on `null`.
- `stringify` of a union of a number or string, an array and `null`, such as `number | number[] | null`, writes `null` for `null`. Before, it threw `JSON numbers must be finite`.
- A model field typed by a string, number or boolean with a required literal brand, such as `string & { readonly __brand: 'Email' }`, accepts its values. Before, its schema required an object too, so every value was rejected.
- A field typed by an indexed access to an anonymous object of a model, such as `billing: TOrder['shipping']`, decodes to a plain object. Before, it became an instance of another model with the same fields, such as `TAddress`.
- A type alias that names a model inside a generic alias whose type parameter has the same name, such as `type Wrap<TAddress> = Pair | null`, keeps the model. Before, the parameter replaced it.
- Two `Pick` or `Omit` projections of one model whose keys read alike in PascalCase, such as `'first-name'` and `'firstName'`, get two names, `TUserPickFirstName` and `TUserPickFirstName2`. Before, generation stopped with [`RUNM1059`](docs/reference/diagnostics.md#runm1059).
- `toWireFormat` and the encode of a model with validation off leave out a required field whose type admits `undefined`, such as `nickname: string | undefined`, when its value is `undefined`, as `stringify` does. Before, the result held the key with the value `undefined`.
- `validateInstance` and `ModelValidator.validate` return the generated issue when an instance rule throws on a field that the generated checks already rejected, such as a rule that reads `title.trim()` when `title` is missing. Before, the call failed with `A custom validation rule could not finish`. See [Instance rules](docs/guide/validation.md#instance-rules).
- `fromWireFormat` and the generated decode reject an invalid `Date` object, such as `new Date(NaN)`, in a date field with a `LibError` of kind `deserialization` and `causedByInput`. Before, the model kept the invalid `Date`, and a later `stringify` threw.
- With validation on, a tuple with fixed elements after its rest element, such as `[string, ...number[], boolean]` or `[...number[], boolean]`, stops generation with [`RUNM1021`](docs/reference/diagnostics.md#runm1021). Before, its validator accepted the rest and the fixed items in any order. Move the fixed elements before the rest element, or set `{ validation: false }` on the model.
- An object with a template literal index signature beside a plain `string` index signature of another value type, such as `{ [k: string]: string; [k: `at_${string}`]: Date }`, stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004). Before, the template keys converted by the `string` signature's type.
- An object with index signatures keyed by template literal types of different value types, such as `` { [k: `a_${string}`]: Date; [k: `n_${string}`]: number } ``, stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004). Before, every value converted by the first type.
- An `int64` number field and an `Integer` field reject a value beyond ±9007199254740991 (`Number.MAX_SAFE_INTEGER`): JSON numbers in JavaScript cannot carry a larger integer exactly, so such a value has already been rounded. Before, `9007199254740993` was accepted as `9007199254740992`. Three optional cases of the JSON Schema test suite (big integers) are excluded for this rule.
- `MultipleOf` compares the exact decimal value: `1000000000000000.5` and `3.000000000000001` are no multiples of `1`, and `0.30000000000000004` is no multiple of `0.1`. Before, a relative tolerance accepted them.
- With validation on, an object keyed by a template literal type, such as `` Record<`id_${string}`, Date> ``, rejects a key outside the template, such as `other`. Before, it accepted any key. A key type that golem cannot state as one pattern, such as `` `${number}` `` or `Uppercase<string>`, stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004). Validation off is unchanged.
- A model `Map`, `Set`, `ReadonlyMap` or `ReadonlySet` field stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004) also with validation off. Before, it generated with a required `size` field and its methods as unknown fields.
- `getObjectCodec` and `getIModelClass` from `@exprtlabs/golem/serde` match the full codec id exactly. Before, a short model name such as `TOrder` also found the codec `TOrder_<8 hex digits>`, and a model named like `Order_0badc0de` was linked wrongly or missed. Pass the id from `.golem/codec-keys.json` or the `codecId` of `model-manifest.json`.
- A number format on a `string` field, such as `string & Format<'int64'>`, stops generation with [`RUNM1051`](docs/reference/diagnostics.md#runm1051). Before, golem accepted it and never checked it.
- When a `TValidation` function throws, or returns neither a boolean nor a string, `parse`, `stringify`, `toWireFormat`, `fromWireFormat`, `validate<T>`, `assertValue<T>`, `validateInstance` and `ModelValidator.validate` throw a `LibError` of kind `Validation` with the message `Model validation could not finish.`, `causedByInput` set to `false` and the original error as `cause`. Before, only `validateInstance` and `ModelValidator.validate` wrapped it; the other calls let the raw error through.
- A model alias whose name starts with `$`, such as `export type $d = IModel<{ id: string }>`, generates when another model file imports it. Before, generation stopped with the TypeError `Unresolved schema reference: $d.`, or the model file failed to compile for a `Date` field.
- `validation` takes `true`, `false` or `'sanity'` in `golem.yaml` and in the options of a model (`IModel<Fields, { validation: 'sanity' }>`). The `sanity` level checks the shape only: JSON types, required keys, extra keys, union tags, enums, `const` values, tuple length and the `date-time` format. It skips value limits (string length, `pattern`, other formats, number ranges, `multipleOf`, array and property counts, `uniqueItems`) and validation functions (`TValidation` and the instance rules of your application). It never rejects a value that the full level accepts. A project at `sanity` writes smaller validators ([Validation profiles](docs/reference/config.md#validation-profiles)).
- `parse`, `stringify`, `fromWireFormat` and `toWireFormat` take `validate: true | 'sanity' | false`. A call can choose any level up to the project level, and off is always allowed. A level above the project throws a `LibError` of kind `ValidationUnavailable`. Any other value throws a `TypeError`. Without the option, a call uses the level of its model, and a nested model is checked at the level of the call ([Choose a level for one call](docs/guide/validation.md#choose-a-level-for-one-call)).
- `validate<T>`, `assertValue<T>`, `validateInstance` and `ModelValidator.validate` take `validate: true | 'sanity'`. At `'sanity'` they skip the instance rules that you add with `extend()`.
- A model can no longer turn validation on above its project. `{ validation: true }` on a model in a project with `validation: false` used to write the checks for that model. Now it stops generation with [`RUNM1089`](docs/reference/diagnostics.md#runm1089), as does `'sanity'` in a project at `false` and `true` in a project at `'sanity'`. Set the model to the level of the project or lower, or raise `validation` in `golem.yaml`. A model with `{ validation: false }` gets no validators, and a call cannot check it.
- `NestModelInterceptor` takes `validate: true | 'sanity'` to choose the level of the request check. Input that fails the check answers HTTP 400 at every level, and a level above the project answers HTTP 500 ([NestJS controllers](docs/reference/nestjs.md#request-validation-level)).
- Fix: a model with `{ validation: false }` that uses a validation function from its own file no longer stops generation.
- Fix: an unnamed object type that several models share validates for every model that holds it, in whatever order the files are read.
- A project that sets `model.suffixes` gets shorter names for a clashing model or a recursive type. Golem now drops the model suffix of the project from the file part of the name. Before, it dropped only `.model` and `.models`: `a.entity.ts` gave `dir.a_entity.Name` and `NodeBEntity`, and now gives `dir.a.Name` and `NodeB`. A project with the default suffixes keeps its names, except that a clashing model in `a.models.ts` is now qualified as `a`, not `a_models`. A project with no models job has no model suffix, so golem drops only the file extension: `a.model.ts` gives `dir.a_model.Name`.
- Validation and encode no longer run a getter that is program state, a key of a model instance that its model does not declare, also inside an `unknown` or `any` field. A `const`, an `enum` and a `uniqueItems` check ignore program state too. Before, they read it, so a throwing getter failed the call.
- Two object tags of a union `discriminator` that differ only in key order, such as `{ x: 1, y: 2 }` and `{ y: 2, x: 1 }`, are one tag, as the generated tag match already read them. Before, they were taken as two tags, so the second branch was unreachable.
- A mapped type that changes its template takes its tags from the template. Before, `{ [K in keyof Tagged]: string }` kept the tags of `Tagged`, so a field such as `PatternProperties<{ [K in keyof X]: string }>` wrongly rejected `{ x_a: 'abcd' }` through the `MaxLength` of `X`.
- A `TValidation` or `TSerde` function that copies the type of another, such as `const b: typeof a`, binds `b` when a mapped type, a type alias argument, a conditional type or `typeof` a variable carries the tag. Before, the field bound `a` in silence, and a field that wrote `typeof b` directly bound `a` as well. Two functions of one type written in one field, a tag that no `typeof` of the field leads back to, or a function tag that an inferred value (`const held = tagged()`, the return of a function, a property of an object) or a base class or interface holds beside a written function of the same type, stop with [`RUNM1040`](docs/reference/diagnostics.md#runm1040).

Before, both stopped with `OPENAPI_COMPOSITION_CONVERSION_CONFLICT`. Give the property one type in every member.
- A `@Query()` model field whose schema is a `$ref` to a named literal-union alias, such as `level: Level` with `type Level = 1 | 2`, decodes from the query string like the same type written inline: `level=2` gives the number `2`.
- A `Map` or `Set` field of a Nest DTO, as a field, an array item, or a body or response root, stops generation with [`RUNM1086`](docs/reference/diagnostics.md#runm1086) unless its `@ApiProperty()` states `type`, `schema` or `additionalProperties`. With one, golem uses that schema. Before, golem wrote an object with a required `size` property.
- `golem-openapi-ts` reads a schema with both `oneOf` and `anyOf` as both: a value matches one `oneOf` branch and one `anyOf` branch, as the generated validator already checked. Before, the generated types and models read only one of the two keywords. Branches that only add `required` names, such as an `anyOf` of `{ required: [email] }` and `{ required: [phone] }`, add no variant; the validator still judges them. When two unions each have several object variants (`oneOf` with `anyOf`, or an `allOf` of two `oneOf`) and a variant holds a `Date` or a model, generation stops with [`OPENAPI_COMPOSITION_CONVERSION_CONFLICT`](docs/reference/diagnostics.md#openapi-composition-conversion-conflict). Before, an `allOf` of two such unions with no model generated code that failed validation on a valid value. Two such unions that convert nothing generate.
- A model field whose schema has `enum` with no `type`, such as `{ enum: [1, 2, 3] }`, or `enum` with a `type`, such as `{ type: 'string', enum: ['a', 'b'] }`, is checked against the listed values by the model validator and the codec. Before, a field with no `type` accepted any value, and a field with a `type` checked only the type. A field with `type: ['string', 'null']` and an `enum` that does not list `null` now rejects `null`, and an empty `enum` accepts no value. An `enum` that lists an object or an array keeps the field's type and rejects a value that does not equal a listed value, compared deeply. Before, such a list left the field unchecked. A required property whose schema is an empty `enum`, `not: true` or `false` stops generation with [`OPENAPI_COMPOSITION_UNSATISFIABLE`](docs/reference/diagnostics.md#openapi-composition-unsatisfiable). Before, golem wrote a model that did not compile.
- A generated client writes a `style: cookie` array or object parameter that sets no `explode` as one cookie for each item or key, as OpenAPI 3.2 sets `explode` to true for `style: cookie` and `style: form`. Before, it wrote one cookie with the items joined by commas.
- A generated client decodes an empty response header that the document declares as an object, with or without `explode`, to `{}`. Before, it threw a `TypeError`.
- A Nest `@Query()` model field that is a tuple, such as `[number, string]`, decodes each position by its own type: `?pair=1&pair=2` gives `[1, '2']`. Before, a tuple field was read as a list of one item type, and a fixed tuple stayed text at every position. An entry after the listed positions follows the rest type of the tuple, and stays text when the tuple has none.
- With `dates: temporal`, `format: duration` means the Temporal wire form in every position of the document, in a body, a parameter, a header and a keyword such as `not` or `if`. The field now accepts the text that Temporal writes, such as `PT0.5S` (fractional seconds), `PT1H30S` and `P1Y2D`. Before, the RFC 3339 `duration` format rejected them, so a `Temporal.Duration` value failed on write and on read. Without `temporal`, a `duration` string keeps the RFC 3339 format.
- A model constructor that throws while golem decodes now makes `parse`, `fromWireFormat` and the Nest interceptor throw `LibError` of kind `Deserialization` with `causedByInput: false` and the exception as `cause`, at the root and in a field, an array item or a record value. Before, the exception reached the caller raw at the root, and inside a field it was `causedByInput: true`, so `NestModelInterceptor` answered HTTP 400. It now answers 500.
- **Breaking:** a `oneOf` of a recursive array component and another array, such as `Tree` and an array of `{ code }`, stops generation with `Union has ambiguous conversions`, as two inline arrays do. The same holds for a `TSerde` whose wire form is an array or tuple, on a class, a model or a recursive array, beside another array. Before, it generated code that read every array with the keys of the other array, so a valid `Tree` lost its keys with no error, and the serde never read an array value. A recursive array component beside a string or `null` converts its items, its dates included. Before, the array stayed as it was on the wire. The same holds for an `IModel` field of a recursive array beside a string: the constructor builds the models in the array, and a decode converts its dates. A recursive array that comes from an SDK of mode `golem`, in a model or an `IObject` over an SDK type, is read the same way: before, the array stayed as it was on the wire. A model that holds an SDK type with a date writes it as JSON text when the call validates: before, the write threw `Expected a valid Date.`
- A model with a date that holds a composed (`allOf`) model of another group, one that holds itself, writes the date of that model as its wire text when it stringifies a validated value. Before, `stringify` threw `Expected a valid Date.`
- A `oneOf` or `anyOf` with a `discriminator` that also holds a `{ const: null }` or `{ enum: [null] }` branch keeps its tag table, as one with `{ type: 'null' }` does. Before, the union lost its discriminator and decoded without the tag.
- The string form of `uriVersioning` is refused with [`NEST1203`](docs/reference/diagnostics.md#nest1203) unless it is `URI` or `uri`, as the `type` of the object form is. Before, it took any case, such as `Uri`.
- A whole `@Query()` typed with a model-level tag, such as `{ status: string } & PatternProperties<{ '^x-': string }>`, gives a `querystring` parameter on OpenAPI 3.2. Before, it stopped with [`NEST1107`](docs/reference/diagnostics.md#nest1107), because the key of the tag counted as a property that has no portable mapping.
- `no-unresolved-refs` reports a discriminator `defaultMapping` pointer that resolves to nothing, as it does a `mapping` pointer. Before, a root document with such a `defaultMapping` passed this rule.
- A `$ref` of the form `#/…` inside a schema that has its own `$id` names a place in that resource when the resource holds it, as JSON Schema 2020-12 says; `no-unresolved-refs` accepts it. Before, `no-unresolved-refs` reported it, and in a referenced file it stopped with `Can't resolve $ref`. A pointer that the resource lacks still names a place in the document, so `#/components/schemas/X` keeps working. A `#/components/schemas/X` pointer names the component `X` of the document first, then a place in the resource, then a place in the document, in the loader and in the generated code alike. The `$id` may be relative. A `$ref` of exactly `#/` names the key `""` (RFC 6901), not the whole resource; `#` is the whole resource. Before, a schema with its own `$id` took `#/` as the whole resource.

A `golem.yaml` can name `tsconfig.build.json` or `tsconfig.app.json`, with its own `paths`. A tsconfig nearer to a job root is not read. The first run after the upgrade runs every `models` and `controllers` job once.
- A `golem.yaml` whose tsconfig is a solution file, one with no files and only `references`, such as the default `tsconfig.json` of a create-vite project, stops `golem generate` and `golem check` with a message that names each referenced project. Name the app's tsconfig, for example `tsconfig.app.json`, in the `tsconfig` key of `golem.yaml`.
- Generated model files call the runtime directly: a model file no longer holds a `modelObject` function, an OpenAPI model module no longer holds an `objectFromJSON` function, a `TSerde` function is imported once and cast, not wrapped in a second function, the plan schemas of both generators are one `JSON.parse` constant, and the runtime imports of both generators come in one order (alphabetical by export name). A model class with a typed map no longer holds the comment line "Dynamic map values are preserved during conversion."
- Generated stringify and conversion code is leaner: a key check compares the key with each name where it ran an `includes` on a list that the code built at each call, an inline object joins its members with one `slice(1)` where it built and joined an array, and an object with no declared field no longer gets a dead `if (false) continue;` in its extra-key loop.
- `@exprtlabs/golem/model` no longer exports the type `GeneratedModelFields`. Use the derived `T<Name>Fields` type that generation writes for the model.
- `@exprtlabs/golem/manifest` no longer exports `manifestMarker`. Nothing in golem called it.
- `GolemProfile.validation` has the type `boolean | 'sanity'`, and `resolveProfile` accepts `true`, `false` and `'sanity'`. A generator that tests `profile.validation === true` must treat `'sanity'` as a level that still validates ([Generator API](docs/reference/generator-api.md)).

- `@exprtlabs/golem/generator-api` no longer exports `ControllerContext`, `ControllerModels`, `ControllerTag`, `ControllerUriVersioning` and `ControllerUriVersioningType`. `@exprtlabs/golem-ts-openapi/generator` exports them. The core decorator reader names no framework package, and the docs job passes the DTO rule (Swagger `@ApiProperty` and the RUNM1086 error for a `Map` or `Set`) as the option `dtoRule` of `createContractAnalysis`.
- **Breaking:** `GeneratorSession.share` and `GeneratorSession.retain` take a `SessionKey<Resource>` as their key, not a `string`. `@exprtlabs/golem/generator-api` exports `sessionKey` and `SessionKey`: make the key once with `const key = sessionKey<MyResource>('name')` and pass it to every request for that resource, so the call returns the type of resource that the first request created. See the [generator API](docs/reference/generator-api.md).
- A job reruns when a file of its generator package that the run loaded has changed, not when any JavaScript file in the package folder has. An app that builds its own generator keeps its build output in that folder without a rerun after each build. The same holds for the package of an extension on the job's hooks.
- Model generation analyzes each model once per job, and a `.model.generated.ts` file emits code only for the models its source declares; models from other sources are referenced by codec id and their generated files are imported. Generation time and output size grow linearly with chains of referencing models (80 chained models: 1.4 s and 4.8 MB, previously 36 s and 284 MB), and models that reference each other across files load in either import order. The generated files of referenced models export internal `__golem*` helpers and an `XInit` type; do not import the helpers directly.
- Validation defaults to on and MobX to off. `allowAny` defaults to false and can be overridden per model.
- Tooling requires Node.js 22.15 or newer.

### Package subpaths

`@exprtlabs/golem` has 15 public subpaths and 17 under `internal/`.

- To convert a model, use `toWireFormat<T>` and `fromWireFormat<T>`, which also validate. `Validator`, `SchemaIssue` and `SchemaIssueDetail` come from `@exprtlabs/golem/validation`. `stringify` and `toWireFormat` reject cyclic input themselves.
- The helpers that only generated code calls are not public. Generated files import them from runtime entries under `internal/`: `model-runtime`, `validation-runtime`, `client-runtime`, `client-validation-runtime` and `temporal-runtime` in `@exprtlabs/golem`, `nest-runtime` in `@exprtlabs/golem-ts-openapi`, and `mobx-runtime` and `mobx-validation-runtime` in `@exprtlabs/golem-openapi-ts`. These entries may change in any release. Generate again after you update golem.
- `@exprtlabs/golem/generator-api`, `rewrite` and `manifest` export only documented names.
- `golem generate`, `check`, `exec`, `watch` and `build` fail unless `@exprtlabs/golem` has exactly the version of each built-in generator package that the configuration uses. Before, a newer runtime of the same major version passed. The error gives the `npm install -D` command that aligns the generator. A package under `generators` keeps its own version and is not compared.
- `@exprtlabs/golem/generator-api` stays public as the extension API: `GolemProvider`, `GeneratorJobContext`, `GolemResult`, `GolemArtifact`, `GolemProfile`, `GolemDiagnostic`, the contexts of the built-in generators, `resolveProfile` and the helpers `stableJson`, `stableValue`, `compareText`, `isInsideDirectory`, `discoverSources`, `parseYamlFile` and `YamlFileError`. It follows semver. An extension generator package needs no other golem import.

See [installation](docs/guide/quick-start.md) for npm commands and release availability.
