# Changelog

This file is the complete list of changes. The documentation site's
[release notes](docs/changelog.md) summarize the release.

## Unreleased

### Models

- `strip: true` in the options of `parse`, `fromWireFormat`, `stringify` and `toWireFormat` removes the keys that a closed object does not declare, at every level and every validation level, before the checks run. The result holds the declared keys only, also for a class. A `Record`, an `AdditionalProperties` tag, pattern properties and an object with `exact: false` keep their extra keys. Types: `DecodeOptions` and `EncodeOptions` from `@exprtlabs/golem/serde`. An encode strips a plain object only: an instance of a class and the value of a `TSerde` field stay as they are, which lets a handler return a database row with an extra column. The default is unchanged. See [`strip`](docs/reference/runtime-api.md#strip).
- A field typed as an intersection of several data parts and a tag, such as `{ a: string } & { b: number } & MinProperties<1>`, keeps every part. Before, only the first part stayed, so a declared field disappeared and valid data failed. A brand beside `string` works in either order.
- A generic tag alias with a compound base, such as `type NonEmpty<T> = T[] & MinItems<1>`, generates. Before, it stopped with `RUNM1003`.
- `Record<number, V>` and `{ [id: number]: V }` convert their values as a string-keyed record does, and reject a key that is no number. Before, they rejected valid data.
- Models whose names differ only in a character that a short name drops, such as `A$` and `A_`, each get their own codec. Before, generation stopped with an unresolved reference.
- `validateInstance` and `ModelValidator.validate` honor `maxDepth`. A function in `.messages()` runs once for each issue.
- A `Date` field reads a leap second, such as `2026-10-06T23:59:60Z`, as second 59, as `Temporal.Instant` does. `Temporal.Instant` reads a fraction of more than nine digits and keeps nine.
- A `UniqueItems` check takes one pass, so a list of any length validates in linear time. It reports the same `unique` issue and `indexes`. Before, the check compared every pair, so one long list could hold the event loop.
- A generated `IModel` constructor writes each field at its own site, so `fromWireFormat` and `new` of a class model run about 1.8 to 1.9 times faster. A field name that the object already reaches, such as an accessor of a subclass, still becomes an own data property, and its setter does not run.
- A model that reaches a recursive model checks `maxDepth` with a walk that allocates no set or map for each node, and `validate` runs about three times faster on a recursive model. The limit and the errors stay the same.
- **Breaking:** a `Date` field now needs an RFC 3339 `date-time` text with an offset, such as `2025-01-02T03:04:05Z`, at every validation level, validation off included. Before, with validation off, texts such as `5`, `2025-01-02` and a time with no offset were read as a date. A Temporal field likewise accepts only its wire form: `20250102` is no longer a `TemporalPlainDate`, and `p1d` is no longer a `TemporalDuration`. A text that does not fit throws `Deserialization` with `causedByInput: true`. The write side follows: `stringify` and `toWireFormat` throw `Serialization` for a value outside the wire form. Before, with validation off, golem wrote such text, such as `2025-01-02[u-ca=gregory]`.
- **Breaking:** a `TSerde` deserializer that throws while golem reads wire input now makes `parse`, `fromWireFormat` and the Nest interceptor throw `LibError` with `causedByInput: true`, in a field, an array item, a record value and a union branch. `NestModelInterceptor` answers HTTP 400 for it. Before, `causedByInput` was `false` and the interceptor answered 500. The exception of a serializer that throws reaches the caller unchanged.
- `Date` and the Temporal classes are built-in `TSerde` types. Golem supplies a default pair of functions for each, and no mechanism of their own remains. A field typed `Date`, `Temporal.Instant`, `Temporal.ZonedDateTime`, `Temporal.PlainDate`, `Temporal.PlainDateTime`, `Temporal.PlainTime` or `Temporal.Duration` converts with no tag, and a plain Temporal field checks the JSON form of its class as the matching `TemporalX` type does. A `TSerde` tag on the type replaces the default. See [Dates and times](docs/guide/field-types.md#dates-and-times).
- **Breaking:** the model value of a `Date` or Temporal field is checked with `instanceof`, as the class of a `TSerde` field is. A value that fails reports one issue with code `instance`, `model` holding the class name, such as `Expected an instance of Date`. An invalid `Date`, such as `new Date(NaN)`, fails too. Before, a `Date` field reported code `type` with `expected: ['Date']`, and that entry of `expected` is gone. A `TSerde` class that a `*.model.ts` file declares now stops generation with [`RUNM1065`](docs/reference/diagnostics.md#runm1065), as a `TSerde` function does. A type with no run-time class, such as an `interface`, has no instance check. The `VALIDATE_UNSUPPORTED_KEYWORD` message for a malformed class check names `golemModelClass`, where it named `golemModelDate` for a `Date`.
- **Breaking:** a `TSerde` field whose JSON value is a string, a number or a boolean reads only that JSON type, at every validation level. Before, with validation off, another JSON value such as `5` for a string skipped the decoder and became the model value. Now it throws `Deserialization` with `causedByInput: true`. A `Date` field also reads only a `date-time` string: `fromWireFormat` no longer accepts a `Date` instance there, such as a database row, with validation off as well as on.
- [`RUNM1052`](docs/reference/diagnostics.md#runm1052) and [`RUNM1085`](docs/reference/diagnostics.md#runm1085) name a Temporal class too, such as `IModel<Temporal.Instant>` and `Temporal.Instant & Model`.
- A `date-time` union that golem cannot convert, such as a `oneOf` of a `date-time` string and a plain `string`, stops with one message for both `dates` values: `A date-time model union must have one Date or Temporal branch and optional null. Ambiguous string branches cannot be converted to Date or Temporal.` Before, the message named `Date` or `Temporal` by the `dates` value.
- **Breaking:** `encodeGeneratedModel` and `decodeGeneratedModel` are deleted. Use `toWireFormat<T>` and `fromWireFormat<T>`. `toWireFormat` validates the model when its profile does and takes `{ validate: false }`. A generated model file has no class-level encoder, and the `encode<Name>` function of a `golem-openapi` model is `toWireFormat<Name>` under a second name.
- A field typed `Date & Model`, `bigint & Model`, or `{ x: Date } & { x: Model }` stops generation with [`RUNM1085`](docs/reference/diagnostics.md#runm1085), with validation on and off. Before, a `Date` field generated a field of `Date`'s method names with validation off and `RUNM1004` blamed `toString` with validation on, and a `bigint` field stopped with an uncoded `TypeError`. A `Date` with a phantom brand, such as `Date & { readonly __brand: 'Timestamp' }`, is a `Date` field, as a branded string or number already was.
- A field typed `Date | Date[]` or `Date | string[]` generates and converts by its wire value: a string is the Date, an array is the array. Before, it stopped with [`RUNM1082`](docs/reference/diagnostics.md#runm1082). A nullable form such as `Date | Date[] | null` keeps `null`.
- A type alias that refers to itself now works in any shape: a union, an array, a tuple or a record. `type JsonValue = null | boolean | number | string | JsonValue[] | { [key: string]: JsonValue }` is a valid field type. Golem generates one function for the alias. [`RUNM1003`](docs/reference/diagnostics.md#runm1003) no longer reports a recursive alias, and [`RUNM1056`](docs/reference/diagnostics.md#runm1056) now means a cycle that golem cannot name.
- A recursive interface or class, such as `interface Tree { kids: Tree[] }`, now generates one schema that refers to itself through `$ref`. Before, generation stopped with a stack overflow. Copies with the same shape, such as one `Node` in two files, share one projection and the plain name. Different shapes, such as `Page<string>` beside `Page<number>`, give the one read second a longer name (`PageNumber`). [`RUNM1059`](docs/reference/diagnostics.md#runm1059) now covers inline types only.
- The longer name of a recursive generic type whose type arguments hold a union, such as `PageEastWest` for `Page<'east' | 'west'>` or `PageRecordEastWestNumber` for `Page<Record<'east' | 'west', number>>`, lists the members of the union in sorted order, and so does the number of a union variant that no written type names. Before, both followed the order in which TypeScript printed the union, so on TypeScript 6 a name could change with the order in which the checker met the literals. A union with `string`, `number`, `null` or `undefined` keeps their places.
- A type that holds `Partial`, `Required`, `Pick` or another mapped type of itself, such as `interface Cfg { patch?: Partial<Cfg> }`, now generates one schema that refers to itself through `$ref`. Before, generation stopped with a stack overflow. A generic type that expands without end, such as `interface Box<T> { next?: Box<Box<T>> }`, stops with [`RUNM1083`](docs/reference/diagnostics.md#runm1083).
- A union of scalars, one array and one object converts and validates without a tag.
- `ModelInit` accepts a value of a type that holds itself through an array, such as `JsonValue`, and no longer stops the compiler with "Type instantiation is excessively deep". A tuple keeps its exact shape.
- `golem-ts-openapi` writes a controller response that has a recursive alias type as one component that refers to itself.
- `golem-openapi` generates a component schema that refers to itself through `$ref`, also when it is not an object, instead of stopping with an error. A model field of it has the type `Types.<Name>`. See [Recursive schemas](docs/reference/openapi-support.md#recursive-schemas).
- A model over a mapped, conditional or `Pick` type keeps the `TSerde` conversion of a field. Before, the field lost it.
- `parse`, `fromWireFormat` and the class-level decode reject a class-model field, array item or record value that is not an object with "<Name>BaseModel expected an object.", an input error at the field's path. Before, with validation off, `'text'` or an array item `5` became an empty model and `null` failed with a plain TypeError that was not marked as caused by input.
- **Breaking:** a registered codec holds no JSON Schema. `ObjectCodec` and `ObjectCodecImpl` lose `schema`, `wireSchema`, `modelOnlySchema`, `wireOnlySchema` and `schemaRefsResolved`, and `@exprtlabs/golem/serde` no longer exports `resolveGeneratedModelSchemaRefs`. A generated model file carries no schema text, so it is smaller and loads without parsing one. `objectCodecValidationReference` returns the codec id for `model` and `Id#plane` for every other plane, `Id#wire` included, also when the wire schema equals the model schema; a generated parse asks a validation context for that key. The OpenAPI document and the validators come from the build, not from a registered codec. `NestModelInterceptor` decodes query strings from the table of the fields that need decoding, which the nest extension of `golem-ts-openapi` writes into the `data` of the codec (the hook `model.codecData`). Core has no `queryFields` on a codec, and `@exprtlabs/golem/serde` no longer exports `QueryFieldShape` and `QueryFieldTable`. A project without `extensions: { nest: {} }` gets no table.
- **Breaking:** a model union of two or more object types, models or SDK types declares its tag key with the `Discriminator` tag from `@exprtlabs/golem/tags`, such as `value: (TEmail | TPhone) & Discriminator<'kind'>`. Golem reads only that key; it no longer looks for a literal property that the variants share. A union without the tag stops with [`RUNM1080`](docs/reference/diagnostics.md#runm1080) at every position and with validation on and off, also when no variant needs conversion. Each object variant declares the key as a required literal with a value of its own, or generation stops with [`RUNM1087`](docs/reference/diagnostics.md#runm1087). The tag on anything other than such a union stops with [`RUNM1051`](docs/reference/diagnostics.md#runm1051). The tag does not change the application type. See [Unions](docs/guide/field-types.md#unions).
- `Discriminator<'kind', TMoney>` names a default variant, the one variant that has no tag, such as an SDK type beside tagged objects. An object whose tag matches no variant decodes as the default.
- A declared default that is not an object, such as `Discriminator<'kind', Date>`, stops generation with [`RUNM1051`](docs/reference/diagnostics.md#runm1051). A scalar, array or `null` variant needs no default: golem picks it by its JSON type.
- An open declared default, such as an SDK type that allows extra keys, takes neither a value that carries another variant's tag nor a model instance of another variant's class. Before, `validateInstance` and the model check accepted such a value as the default.
- `stringify` and `toWireFormat` tell a model instance of a tagged union by its class first: a tag-less `Email` instance is written as the `Email` variant with its tag, and an instance whose tag names another variant throws. Before, the default variant wrote it and dropped its fields.
- Strings, numbers, booleans, literals, one array or tuple, and `null` can sit beside the tagged objects of a union, as in `((string | TEmail | TPhone) & Discriminator<'kind'>) | null`. Golem picks a value by its JSON type first, then an object by its tag, then the default.
- A `TSerde` class value whose JSON form is a scalar, such as `URL & TSerde<typeof encodeUrl, typeof decodeUrl>` with a string wire, can sit beside the tagged objects of a union, as in `(Link | TEmail | TPhone) & Discriminator<'kind'>` or `Link | ((TEmail | TPhone) & Discriminator<'kind'>)`. It writes, reads and validates with validation on and off. An object beside the class value goes to its own variant: a model instance or a plain object is a tagged variant, and any other object goes to the serializer of the class value. Before, generation stopped with [`RUNM1082`](docs/reference/diagnostics.md#runm1082). A `TSerde` value written as an object or an array beside tagged objects still stops with `RUNM1082`.
- The generated names of the variants of a tagged union come from the values of the declared key. Before, they came from the first literal property that the variants shared; names stay the same where that was the same key.
- Any other union that golem cannot convert without trying its variants stops generation with [`RUNM1082`](docs/reference/diagnostics.md#runm1082). The message names the model file and lists the variants. Before, the message had no code and no file.
- A syntax error in a model source, such as a half-typed field, stops generation with the compiler's own error and its file and line. Before, it was reported as [`RUNM1011`](docs/reference/diagnostics.md#runm1011).
- [`RUNM1053`](docs/reference/diagnostics.md#runm1053) points at the inline `IObject` or `IModel` definition that it rejects, such as one variant of a union, and shows its text. [`RUNM1058`](docs/reference/diagnostics.md#runm1058) from the controllers job adds the first TypeScript error at its position, such as `TS2304: Cannot find name 'strin'`, so a broken model gives the same cause when the watch starts and after an edit.
- `fromWireFormat` of a cyclic value with validation on throws a `LibError` of kind `deserialization`, not a stack overflow.
- On the first `golem generate`, a utility type over a class of your app resolves its fields. This holds for an inline mapped type such as `{ [K in keyof Customer]: Customer[K] }`, a utility type that you wrote, `Partial<Pick<Customer, 'name'>>` and an indexed access. Before, these stopped with [`RUNM1058`](docs/reference/diagnostics.md#runm1058) or gave unknown fields until the second run.
- A model defined by a mapped type over its own class still stops with [`RUNM1058`](docs/reference/diagnostics.md#runm1058). The message now names the model and the class, and tells you to declare the fields in the model.
- A tagged field that you reach through `Pick` keeps its validation tag on every run. Before, the second run dropped the tag.
- `TValidation` and `TSerde` accept functions that you declare as typed consts, such as `export const check: (v: string) => boolean = ...`. A nullable union member that you write through a tag alias, such as `Inner<5> & string | null`, now stops generation with [`RUNM1064`](docs/reference/diagnostics.md#runm1064). Before, it generated a validator that rejected every plain string.
- An `IModel` or `IObject` whose fields type is not an object type, such as `IModel<string[]>`, `IObject<Date[]>` or `IModel<string>`, or is a type that a `TSerde` converts as a whole, stops generation with [`RUNM1052`](docs/reference/diagnostics.md#runm1052), and the message names what it found. Before, an array root wrote an invalid model file or stopped with a wrong [`RUNM1004`](docs/reference/diagnostics.md#runm1004), and a whole-object `TSerde` root wrote a file that did not compile. A root union keeps the same code. A fields type that does not resolve, such as a missing import, stops with [`RUNM1058`](docs/reference/diagnostics.md#runm1058).
- A property with a symbol key, such as `[sym]: string`, in a model, in a nested object of a model or in the type of a controller parameter stops generation with [`RUNM1070`](docs/reference/diagnostics.md#runm1070). Before, a model wrote a field named `__@sym@4`, and a parameter became a query or header parameter with that name.
- Validation of an object type with no named properties is faster, and `stringify` of a map of numbers, such as `{ [key: string]: number }`, is faster. The results are the same.
- A `MultipleOf` check with a decimal divisor such as `MultipleOf<0.1>` is faster. Every value gets the same result.

- A model `number` field can carry `Format<'int32'>`, `Format<'int64'>`, `Format<'float'>` or `Format<'double'>`. Its schema gets the `format`, and the generated validator rejects a value out of range, such as `2**31` for `int32` or `Infinity` for `double`.
- Model output built with validation off no longer carries validation bindings in its generated wire schema.
- [`RUNM1004`](docs/reference/diagnostics.md#runm1004) for a model `Map` or `Set` field names `Map` or `Set`. Before, it named one of their methods.
- A derived model that narrows an array-of-models field, such as `IModel<TOwner & { pets: TCat[] }>` where `TOwner` has `pets: TPet[]`, decodes the items as `TCat` model instances. Before, the items stayed plain objects.
- A `TSerde` whose wire type is a `number` or a `boolean` runs its deserializer when golem decodes the field. Before, `parse` and `fromWireFormat` returned the wire value unchanged.
- The generated code of a tagged model union holds its class-and-tag dispatch once, as one module-level selector per direction that every writer and reader of the file shares. Generated files with tagged unions are about a fifth to two fifths smaller.
- `stringify` and `toWireFormat` write a `Date` beside the objects of a union as its ISO string, as in `(TEmail | TPhone | Date) & Discriminator<'kind'>` or `TEmail | Date | string[]`. Before, the tagged form threw `Unknown kind discriminator value` and the untagged form kept the `Date` object.
- A model that reaches a recursive model rejects input nested deeper than `maxDepth` (512 levels of objects and arrays by default) with a `LibError` of kind `deserialization` and `causedByInput` on `parse`, `fromWireFormat` and `assert`; `validate` answers `false`. `NestModelInterceptor` answers HTTP 400 and takes `maxDepth` as an option. Before, a deeply nested body overflowed the stack and answered 500. A model that reaches no recursive model is not walked. See [maxDepth](docs/reference/runtime-api.md).
- A union of a `TSerde` scalar and `null`, also beside a tagged union, decodes `null` as `null`. Before, the deserializer ran on `null`.
- `stringify` of a union of a number or string, an array and `null`, such as `number | number[] | null`, writes `null` for `null`. Before, it threw `JSON numbers must be finite`.
- A model field typed by a string, number or boolean with a required literal brand, such as `string & { readonly __brand: 'Email' }`, accepts its values. Before, its schema required an object too, so every value was rejected.
- A field typed by an indexed access to an anonymous object of a model, such as `billing: TOrder['shipping']`, decodes to a plain object. Before, it became an instance of another model with the same fields, such as `TAddress`.
- A type alias that names a model inside a generic alias whose type parameter has the same name, such as `type Wrap<TAddress> = Pair | null`, keeps the model. Before, the parameter replaced it.
- Two `Pick` or `Omit` projections of one model whose keys read alike in PascalCase, such as `'first-name'` and `'firstName'`, get two names, `TUserPickFirstName` and `TUserPickFirstName2`. Before, generation stopped with [`RUNM1059`](docs/reference/diagnostics.md#runm1059).
- `toWireFormat` and the encode of a model with validation off leave out a required field whose type admits `undefined`, such as `nickname: string | undefined`, when its value is `undefined`, as `stringify` does. Before, the result held the key with the value `undefined`.
- `validateInstance` and `ModelValidator.validate` return the generated issue when an instance rule throws on a field that the generated checks already rejected, such as a rule that reads `title.trim()` when `title` is missing. Before, the call failed with `A custom validation rule could not finish`. See [Instance rules](docs/guide/validation.md#instance-rules).
- `fromWireFormat` and the generated decode reject an invalid `Date` object, such as `new Date(NaN)`, in a date field with a `LibError` of kind `deserialization` and `causedByInput`. Before, the model kept the invalid `Date`, and a later `stringify` threw.
- **Breaking:** with validation on, a tuple with fixed elements after its rest element, such as `[string, ...number[], boolean]` or `[...number[], boolean]`, stops generation with [`RUNM1021`](docs/reference/diagnostics.md#runm1021). Before, its validator accepted the rest and the fixed items in any order. Move the fixed elements before the rest element, or set `{ validation: false }` on the model.
- **Breaking:** an object with a template literal index signature beside a plain `string` index signature of another value type, such as `{ [k: string]: string; [k: `at_${string}`]: Date }`, stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004). Before, the template keys converted by the `string` signature's type.
- **Breaking:** an object with index signatures keyed by template literal types of different value types, such as `` { [k: `a_${string}`]: Date; [k: `n_${string}`]: number } ``, stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004). Before, every value converted by the first type.
- **Breaking:** an `int64` number field and an `Integer` field reject a value beyond ±9007199254740991 (`Number.MAX_SAFE_INTEGER`): JSON numbers in JavaScript cannot carry a larger integer exactly, so such a value has already been rounded. Before, `9007199254740993` was accepted as `9007199254740992`. Three optional cases of the JSON Schema test suite (big integers) are excluded for this rule.
- **Breaking:** `MultipleOf` compares the exact decimal value: `1000000000000000.5` and `3.000000000000001` are no multiples of `1`, and `0.30000000000000004` is no multiple of `0.1`. Before, a relative tolerance accepted them.
- **Breaking:** with validation on, an object keyed by a template literal type, such as `` Record<`id_${string}`, Date> ``, rejects a key outside the template, such as `other`. Before, it accepted any key. A key type that golem cannot state as one pattern, such as `` `${number}` `` or `Uppercase<string>`, stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004). Validation off is unchanged.
- **Breaking:** a model `Map`, `Set`, `ReadonlyMap` or `ReadonlySet` field stops generation with [`RUNM1004`](docs/reference/diagnostics.md#runm1004) also with validation off. Before, it generated with a required `size` field and its methods as unknown fields.
- **Breaking:** `getObjectCodec` and `getIModelClass` from `@exprtlabs/golem/serde` match the full codec id exactly. Before, a short model name such as `TOrder` also found the codec `TOrder_<8 hex digits>`, and a model named like `Order_0badc0de` was linked wrongly or missed. Pass the id from `.golem/codec-keys.json` or the `codecId` of `model-manifest.json`.
- **Breaking:** a number format on a `string` field, such as `string & Format<'int64'>`, stops generation with [`RUNM1051`](docs/reference/diagnostics.md#runm1051). Before, golem accepted it and never checked it.
- **Breaking:** when a `TValidation` function throws, or returns neither a boolean nor a string, `parse`, `stringify`, `toWireFormat`, `fromWireFormat`, `validate<T>`, `assertValue<T>`, `validateInstance` and `ModelValidator.validate` throw a `LibError` of kind `Validation` with the message `Model validation could not finish.`, `causedByInput` set to `false` and the original error as `cause`. Before, only `validateInstance` and `ModelValidator.validate` wrapped it; the other calls let the raw error through.
- A model alias whose name starts with `$`, such as `export type $d = IModel<{ id: string }>`, generates when another model file imports it. Before, generation stopped with the TypeError `Unresolved schema reference: $d.`, or the model file failed to compile for a `Date` field.
- `validation` takes `true`, `false` or `'sanity'` in `golem.yaml` and in the options of a model (`IModel<Fields, { validation: 'sanity' }>`). The `sanity` level checks the shape only: JSON types, required keys, extra keys, union tags, enums, `const` values, tuple length and the `date-time` format. It skips value limits (string length, `pattern`, other formats, number ranges, `multipleOf`, array and property counts, `uniqueItems`) and validation functions (`TValidation` and the instance rules of your application). It never rejects a value that the full level accepts. A project at `sanity` writes smaller validators ([Validation profiles](docs/reference/config.md#validation-profiles)).
- `parse`, `stringify`, `fromWireFormat` and `toWireFormat` take `validate: true | 'sanity' | false`. A call can choose any level up to the project level, and off is always allowed. A level above the project throws a `LibError` of kind `ValidationUnavailable`. Any other value throws a `TypeError`. Without the option, a call uses the level of its model, and a nested model is checked at the level of the call ([Choose a level for one call](docs/guide/validation.md#choose-a-level-for-one-call)).
- `validate<T>`, `assertValue<T>`, `validateInstance` and `ModelValidator.validate` take `validate: true | 'sanity'`. At `'sanity'` they skip the instance rules that you add with `extend()`.
- **Breaking:** a model can no longer turn validation on above its project. `{ validation: true }` on a model in a project with `validation: false` used to write the checks for that model. Now it stops generation with [`RUNM1089`](docs/reference/diagnostics.md#runm1089), as does `'sanity'` in a project at `false` and `true` in a project at `'sanity'`. Set the model to the level of the project or lower, or raise `validation` in `golem.yaml`. A model with `{ validation: false }` gets no validators, and a call cannot check it.
- `NestModelInterceptor` takes `validate: true | 'sanity'` to choose the level of the request check. Input that fails the check answers HTTP 400 at every level, and a level above the project answers HTTP 500 ([NestJS controllers](docs/reference/nestjs.md#request-validation-level)).
- Fix: a model with `{ validation: false }` that uses a validation function from its own file no longer stops generation.
- Fix: an unnamed object type that several models share validates for every model that holds it, in whatever order the files are read.
- A project that sets `model.suffixes` gets shorter names for a clashing model or a recursive type. Golem now drops the model suffix of the project from the file part of the name. Before, it dropped only `.model` and `.models`: `a.entity.ts` gave `dir.a_entity.Name` and `NodeBEntity`, and now gives `dir.a.Name` and `NodeB`. A project with the default suffixes keeps its names, except that a clashing model in `a.models.ts` is now qualified as `a`, not `a_models`. A project with no models job has no model suffix, so golem drops only the file extension: `a.model.ts` gives `dir.a_model.Name`.

### OpenAPI

- **Breaking:** a `@ApiBody()` that does not set `required` writes `required: true`, as `@nestjs/swagger` does, also on `@Body() body?: Dto`.
- **Breaking:** a header parameter named `Accept`, `Content-Type` or `Authorization` is ignored, as OpenAPI says, with the warning [`OPENAPI_RESERVED_HEADER`](docs/reference/diagnostics.md#openapi-reserved-header). It leaves the generated input.
- **Breaking:** a spread or a computed key in `@Controller({ ... })` stops with [`NEST1201`](docs/reference/diagnostics.md#nest1201). Before, the path was dropped with no error.

### Models

- **Breaking:** generated names keep the exact type alias; golem no longer drops a leading `T` or a trailing `Model`. `type TPayment = IModel<…>` generates `TPaymentBaseModel`, `TPaymentFields`, `TPaymentJSON` and `TPaymentInit` (it was `PaymentBase`, `PaymentFields`, `PaymentJSON` and `PaymentInit`), and its functions use the alias, such as `parseTPayment`. `type Payment = IModel<…>` generates `PaymentBaseModel`; `type TPermissionModel = IModel<…>` generates `TPermissionModelBaseModel`. Regenerate and update `extends`.
- **Breaking:** your class links to its model through `extends <Alias>BaseModel`, not through its name, so `class PurchaseOrder extends TOrderBaseModel` works. Every exported class of the model's file that extends the generated base directly links to the model and gets its own plugin key, so `parse<AdminPayment>` builds an `AdminPayment`; a subclass of a linked class does not link. A model with one linked class uses it as its default class. - A name in the `required` list of any `allOf` member is required in the generated TypeScript type wherever a member declares the property, as the validator already required it (`allOf: [{ $ref: Pet }, { required: [name] }]` makes `name` required in that type; `Pet` itself is unchanged), including inside the `oneOf` and `anyOf` branches of an `allOf` member, and a schema's own `required` names that it does not declare itself apply to its own `oneOf` and `anyOf` branches.
- Fixed: a generated model's `prefixItems` tuple field converts each item by its own schema. With `prefixItems: [{ type: string }]` and `items: { type: string, format: date-time }`, the first item stays a string and the rest decode to `Date`; before, every item was converted as a `Date`, so the string failed to decode. The field type is the tuple (`[] | [string] | [string, ...Date[]]`), not `Date[]`, and a tuple with `items: false` converts its items too. The type of a tuple field changes with its items: `[string]` becomes `[Date]` for a `date-time` item, and `[Types.Pet]` becomes `[PetModel]` for a model item. An ambiguous union inside a prefix item now fails generation; it used to generate without conversion.
- Fixed: a generated model's array or `prefixItems` tuple field converts its items by its own schema when its `allOf` members only add constraints or a description, such as `allOf: [{ minItems: 1 }]`. Before, `items: { type: string, format: date-time }` was typed `Date[]` but the values stayed strings, so `.getTime()` threw at runtime. When exactly one `allOf` member declares the array and converts its items, that member decides both the type and the conversion. A tuple with such an `allOf` is now typed by its items too (`[] | [string]` becomes `[] | [Date]` for a `date-time` item).
- Fixed: a generated model's array or `prefixItems` tuple field with no `type`, or with `type: [array, null]`, converts and is typed like `type: array`. Before, `items: { type: string, format: date-time }` beside `type: [array, null]` stayed `string[] | null`; now it decodes to `Date[] | null`, and `null` stays `null`. The same holds for such a schema as a `oneOf` branch beside a scalar.
- Fixed: a generated model's object or `oneOf` field converts by its own `properties` or `oneOf` when its `allOf` members only add constraints or a description, such as `allOf: [{ minProperties: 1 }]`. Before, `properties: { at: { type: string, format: date-time } }` was typed `{ at?: Date }` but `at` stayed a string, so `.getTime()` threw at runtime; the same held for a `oneOf` with a `date-time` branch. The constraints still apply. When an `allOf` member declares the object itself, that member decides the conversion.
- Fixed: a generated model's inline nullable object field (`type: [object, null]` with `properties` or `additionalProperties`) admits `null` and is typed with `| null`. Before, validation rejected `null` and the type was the object alone, `{ at?: Date }`. The same holds when its `allOf` members only add constraints, such as `allOf: [{ minProperties: 1 }]`; an empty object still fails the constraint.
- Fixed: a generated model field that references a nullable component object (`Pet: { type: [object, null] }`, `pet: { $ref: Pet }`) is typed `PetModel | null` and its validator admits `null`. Before, the field type was `PetModel` and validation rejected `null` with `PetModel expected an object`. A `oneOf` or `anyOf` variant that references such a component admits `null` and is typed `| null`, unless the union has a `discriminator`; a discriminated union keeps its variants non-null.
- Fixed: a generated model's inline object field with its own `properties` and an `allOf` member that declares properties is typed and converted from both. With `properties: { at: date-time }` and `allOf: [{ properties: { b: date-time } }]`, the type is `{ at?: Date; b?: Date }`, and `at` and `b` both decode to `Date`. Before, the type held only `at` while the conversion read only `b`, so `at` stayed a string.
- Fixed: a generated model's inline object field takes the names in the `required` list of its `allOf` members as required, in the type and in the validator. With `properties: { at: date-time }` and `allOf: [{ required: [at] }]`, the type is `{ at: Date }` and `{}` fails validation; before, `at` was optional in both.
- Fixed: a generated model's inline field that is an `allOf` of object members with no keywords of its own is typed from the same members that convert it. With members that declare `at` and `b` as `date-time`, the type is `{ at?: Date; b?: Date }`. Before, it was `{ at?: string } & { b?: string }` while both decoded to `Date`.
- Fixed: a generated model field that is an intersection of objects (an `allOf` of object members, or own `properties` beside an `allOf` member that adds properties) converts every member's fields on the codec path too. With `date-time` fields in two members, `fromWireFormat` decoded neither to `Date`, and it failed validation with `Expected Date`; now both decode and `toWireFormat` writes them back.
- **Breaking:** `additionalProperties` in an `allOf` member follows JSON Schema: the member judges each name that its own `properties` do not list, also the names that its sibling members list. With `allOf: [{ properties: { a }, additionalProperties: false }, { properties: { b } }]`, `b` cannot hold a value. Generation types `b` as `never` and warns with `OPENAPI_COMPOSITION_PROPERTY_NEVER`. A required `b` stops generation with `OPENAPI_COMPOSITION_UNSATISFIABLE`. To close a component that extends a base, remove `additionalProperties: false` from the base and add `unevaluatedProperties: false` to the component.
- `unevaluatedProperties: false` on a component that extends a base through `allOf` limits the object to the names that the base and the component list, and the validator rejects other names. A field that is `allOf: [{ $ref: Pet }]` with `unevaluatedProperties: false` limits `PetModel` to the names of `Pet` in the same way.
- An `allOf` that no object satisfies stops generation with `OPENAPI_COMPOSITION_UNSATISFIABLE`, and an `allOf` whose members convert one property in two ways, such as to two different models, stops it with `OPENAPI_COMPOSITION_CONVERSION_CONFLICT`. Before, such a schema generated code that read only some of its members.
- Fixed: a field that joins a `$ref` and properties in one object, as `allOf: [{ $ref: Base }, { properties: { at } }]` or as own `properties` beside `allOf: [{ $ref: Base }]`, is one plain object with the fields of `Base` and its own fields, in the type, the model and the codec. Before, own properties beside the `$ref` lost the fields of `Base`. A component with the same `allOf` still extends `BaseModel`, and a field that is only `allOf: [{ $ref: Pet }]` stays a `PetModel`.
- **Breaking:** `null` in an `allOf` follows JSON Schema: the object admits `null` only when each member that declares a `type` admits `null`. `{ type: [object, null], allOf: [{ $ref: Pet }] }` now rejects `null` when `Pet` is `type: object`. To admit `null`, use `oneOf: [{ $ref: Pet }, { type: 'null' }]`.
- A model with an explicit `additionalProperties: true` now writes its extra keys in `stringify` and `toWireFormat`. Before, they wrote only the declared fields. Its codec id changes, so regenerate. A model that is open only by the JSON Schema default still writes its declared fields only.
- The generated constructor and `decode` of an OpenAPI model read only the own enumerable fields of their input, once each. Before, they also read inherited values and ran a getter twice. The generated `encode` writes each declared field once, also when a getter or an inherited value supplies it. Regenerate.
- An `allOf` of a base model and a `oneOf` or `anyOf` generates a union of merged objects, one for each variant. The type, the constructor input and the validator agree. A field or component with an `allOf` beside its own `oneOf` or `anyOf` is typed and converted as the `allOf` and the union together.
- **Breaking:** a component with an `allOf` beside its own `oneOf` or `anyOf`, or with an `allOf` that holds a `oneOf` or `anyOf` member, is a type alias of the union of merged objects. Before, it was a class that extended the `allOf` and dropped the union. Build the value of a variant through its init type. Do not extend the alias or construct it. Its variants need a unique, required literal discriminator, as for any object union.
- A model beside a union that cannot be spread, such as a base that meets two unions or a variant that is not an object, stops generation with `OPENAPI_COMPOSITION_CONVERSION_CONFLICT`. A conflict between `allOf` members in an inline operation parameter, body or response schema stops generation as it does under `components`. Before, it generated silently.
- Fixed: a component with two base references, such as `Cat: allOf: [Pet, Named]`, counts both bases when it narrows a property. Before, it failed as a conversion conflict.
- Fixed: a `oneOf` of a model reference and a string keeps both branches, in the type and in the codec.
- Fixed: a field that widens a nullable component reference with `null` keeps the component's conversions, so a nullable component with a `date-time` property validates and decodes.
- Fixed: a composed `allOf` root with `additionalProperties: true`, also over a model base, keeps its extra keys in `stringify` and `toWireFormat`. Regenerate.
- Fixed: the class-level decode of a model reads the declared fields of a nested object as `JSON.stringify` does, so an inherited, non-enumerable or `undefined` field is absent.
- **Breaking:** stacked `@ApiHeader` and `@ApiQuery` decorators list their parameters in the order `@nestjs/swagger` applies them. The order of the parameters in a generated document can change. Regenerate, and read parameters by name, not by position.
- Fixed: a controller path can be an enum member or a `const` object member.

See [OpenAPI support](docs/reference/openapi-support.md) for supported versions and contract limitations.

### Validation

- **Breaking:** a union of models of the same job gets the discriminator of its inline form when each model has a required string tag with a value of its own. Its schema is `oneOf` with `discriminator`, not `anyOf`. A value with a wrong tag gets the issue of the tag (`literal` at the tag property), not `union` with `matched: 0`. A value with a known tag gets the issues of its model. The OpenAPI document that golem-ts-openapi writes gets `discriminator` with a `mapping` from each tag to the `$ref` of its model. A union with a model of another job keeps `anyOf`.
- **Breaking:** Ajv is removed. golem validates with validators it generates, in one mode; `ajv` and `ajv-formats` are no longer peer or optional dependencies. The `@exprtlabs/golem/ajv` and `@exprtlabs/golem/ajv-tooling` subpaths, `OpenApiAjvOptions`, `createOpenApiAjvEngine`, `createOpenApiSyncAjvEngine`, `configureModelValidationEngine` and `registerModelValidationEngineFactory` are removed.
- **Breaking:** `ajvStandalone` is removed from `golem.yaml` and `GolemProfile`; the key is now an unknown-key error.
- **Breaking:** `golem.yaml` gains `unknownFormats: error | warn`, and the default `error` stops generation with `VALIDATE_UNKNOWN_FORMAT` on a schema `format` that golem does not check. Set `unknownFormats: warn` to report it as a warning and skip its check. golem checks `byte`, `json-pointer` and `relative-json-pointer`; Ajv also checked `uri-template`, `url`, `iso-time` and `iso-date-time`, which are not checked now.
- **Breaking:** validators are written as TypeScript: `models.validators.generated.ts`, `_<group>.validators.generated.ts` and `operations/<name>.validators.generated.ts`, with no notices file. The next generate deletes the old `.js`, `.d.ts` and `.NOTICES.txt` outputs.
- **Breaking:** issue codes describe the kind of failure (`type`, `required`, `tooSmall`, `tooBig`, `literal`, `unknownKey`, `invalidKey`, `union`, `instance`, `pattern`, `format`, `multipleOf`, `unique`, `not`, `never`, `custom`) with typed fields. The per-keyword codes and `params` are gone, and the default English messages changed. `IssueCode` is a string-union type, no longer an enum: `IssueCode.Required` no longer compiles, so use the string codes. The HTTP 400 body of a NestJS application carries the new issue shape (no `params`); update clients that read it.
- **Breaking:** `ValidationRuleResult` takes `{ message }` only; an issue from a rule has the code `custom`. `ModelValidationContext` is `{ resolve }`; `engine` is removed.
- **Breaking:** `ClientRuntime` loses `defaults`, `createValidationEngine` and `validationEngine`. A client's `operationValidators` override is a `Validator`, `(value, all)` returning an array of issues; any other result throws `TypeError`. `ValidationResult` is `{ valid, issues }`, and `validateWith` takes `all`.
- A property whose value is `undefined` counts as absent. The `source` of an issue from a nested model is the source of the model that holds it.
- **Breaking:** Golem now treats a field as present only when it is an own enumerable property with a defined value, as `JSON.stringify` writes it, in validation, decode, constructors and `validateInstance`. `new Model({ a: undefined })` and `decodeGeneratedModel` no longer define an own `a`. With `validate: false`, `fromWireFormat` and `parse` skip a field whose value is `undefined`, required and converted fields included, and an undeclared key whose value is `undefined`. A union tag that is inherited or not enumerable selects no variant. In `const`, `enum`, `uniqueItems` and tags, `[undefined]`, a hole and `[null]` are equal, so `uniqueItems` now rejects arrays whose items differ only by `undefined`-valued keys or items (`[undefined, null]` has a duplicate pair), and `const` and `enum` accept a value with an extra `undefined`-valued key. A prototype accessor no longer supplies a declared field in `validateInstance` (consistent with `codec.validate`, and with `toWireFormat` and `stringify` under validation on). Encoding still reads each declared field as a property. Encoding (`toWireFormat`) also drops an extra key whose value is `undefined`; the JSON text is the same.
- Generated model validators answer a valid value with a fast boolean check, `is_<Name>`, written beside `validate_<Name>`; validation results, issues, errors and messages are the same, and a value that fails and a `validationContext` take the full validator as before. A model has no fast check, and keeps the full validator, when it reaches a `TValidation` function, or when its own checks use `unevaluatedProperties` or `unevaluatedItems` (a parent that refs it still gets the fast check). The validators module exports the fast checks. Each generated validate and assert function calls its fast check first, and the validators call the new runtime helper `formatTest`. Newly generated files need this runtime: with an older one, they fail at import with a missing export.
- Checking a `date-time` string is about six times faster, so decode, encode, parse and stringify with validation on run 1.2 to 2 times faster on models with a date. A string is valid or invalid exactly as before.
- Fixed: in `const`, `enum`, `uniqueItems` and tags, an array hole no longer matches any value.
- Every array keyword (`items`, `prefixItems`, `contains` and `uniqueItems`) reads an `undefined` item as `null`, and `stringify` of `(string | null)[]` with an `undefined` item writes `null`. An array with a hole is not valid: the validator reports one `type` issue at the index of the hole.
- **Breaking:** an SDK generated by an older release, without `validationSchemaClosure` in its `model-manifest.json`, fails generation in every project that uses its models, with validation on or off. Regenerate the SDK.
- **Breaking:** a field typed `unknown` fails generation with `RUNM1011`, as `any` does, unless `allowAny` is `true` in `golem.yaml` or in the model's options. This includes the parameter of a `TSerde` deserializer. `RUNM1011` is now titled "Field contains any or unknown"; its fix is a concrete type or `allowAny: true`.
- **Breaking:** `$dynamicRef` and `$dynamicAnchor` in an external OpenAPI document fail generation with `VALIDATE_UNSUPPORTED_KEYWORD`.
- `golem.yaml` gains the root key `exact` (default `true`). It is the default for the `exact` option of every model that sets none; the model option overrides it.
- With validation off, `stringify` and `toWireFormat` write the declared fields that an object has and leave out a missing required field. Before, a missing required field threw a `TypeError` or was written as an invented default. A validated call still rejects the object.

### Generation

- **Breaking:** `ttsc` and the Go plugin are removed, with the `@exprtlabs/golem/ttsc-plugin` and `@exprtlabs/golem-ts-openapi/ttsc-plugin` subpaths and the `ttsc` peer dependency of every package. - **Breaking:** `golem.yaml` gains the `tsconfig:` key (default `tsconfig.json` beside it) and is the entry point for `golem build`. One `golem.yaml` serves one tsconfig: the `root` of a `models` or `controllers` job must lie inside its directory, and the tsconfig must be the one the job finds.
- **Breaking:** the codec-key table of your own models moves from `src/generated/models/iobject-plugin-keys.ts` to `.golem/codec-keys.json` in the directory of `golem.yaml`. The `model-manifest.json` of an SDK gains a `codecId` for each entry of `models`, and the SDK stops writing `iobject-plugin-keys.ts`. Tables of SDKs generated before this release are not read. Regenerate your SDKs.
- Generated files are not committed. Ignore the generated files and `.golem/`. A second `golem generate` or `golem build` with no change runs no job.
- After a failed `golem generate` run, the next run reruns each job whose output no longer matches its input. Before, it could keep stale output.
- `golem generate` and `golem build` on a clean clone accept an OpenAPI `input` or a models `sources` entry that an earlier generator or `openapi` job writes. An input that no job writes still fails with `does not exist`.
- `models.suffixes` and `controllers[].suffixes` choose the file endings that mark a model or a controller (`.mts` and `.cts` too). A generated file puts `.generated` before the final extension of its source, so `order.entity.ts` gets `order.entity.generated.ts`.
- Generation stops only on a type error in the models job's own model sources and in the files it writes. A type error in another handwritten file no longer stops `golem generate`; `tsc` and `golem build` report it. Editing any project source runs the models job again, because it reads the whole project.

With `preserveSymlinks`, a `parse<T>()` call in a symlinked workspace package fails at run time, not in the build tool. A generator that lists `watchInputs` it never announced through `onInput` runs on every build.
- `golem build [--config golem.yaml] [-p tsconfig.build.json] [--watch] [tsc arguments...]` generates first, type-checks your original sources with your TypeScript, then emits JavaScript with the generic serde calls rewritten from a staged copy. Like `tsc`, it emits after type errors unless `noEmitOnError` is set. It passes every other argument to `tsc`, and `-w` means `--watch`. It rejects the arguments it sets itself (`--noCheck`, `--noEmit`, `--emitDeclarationOnly`, `--tsBuildInfoFile`, `--incremental`, `--outDir`, `--listEmittedFiles`, `--rootDir`, `--baseUrl`, `--composite`, `--outFile`, `--declarationDir`, `--sourceRoot`, `--mapRoot`, `--inlineSourceMap` and `--inlineSources`) and says what to set in the tsconfig. It rejects a missing `outDir`, project references (`-b`), `outFile`, `rootDirs`, `inlineSourceMap` and `sourceRoot`. Its state lives in `.golem/build/<tsconfig name>/`.
- `golem build`, `golem check`, the Vite and esbuild plugins and the Node loader accept every file the tsconfig includes, as `tsc` does, including files outside its directory such as `../shared/*.ts`, and rewrite the `parse<T>()` calls in them. The diagnostic RUNM1070 no longer exists.
- **Breaking:** a shared folder or package declares models, and each app generates them in its own `models.output`. A model file whose real path is inside `models.root` is the app's own, and its generated file stays beside it; golem follows folder links to find the real path. Every other model file is a shared model file: a plain include, a folder link, a linked workspace package and a package in `node_modules` work the same way, and a declaration file such as `customer.model.d.ts` counts. An `IModel` or `IObject` alias in a shared model file is a model of the app. The app writes its generated file at `<models.output>/<package name>/<path in the package>.generated.ts`. The package is the nearest folder above the file whose `package.json` has a `name`, else the top folder below the folder that holds both the file and your `golem.yaml`. Your class that extends the generated base class stays in the app and imports the base from `models.output`; two apps can add different methods to one shared model. Golem writes nothing into a shared folder and takes no lock there. A plain type of a shared folder is a field type of an app model, and its constraints apply. A `TSerde` or `TValidation` function of a shared folder works in an app model; the ids of functions outside the root are relative to the root. The layer `models.generated.ts`, the specifier `#golem-models` and the lock `.golem.lock` are gone, so a tool outside golem needs no `imports` entry, alias or `paths` entry. Each `<name>.model.generated.ts` fixes the profile of the app, holds its own schemas, and imports only its own validators, by relative path, from `models.validators.generated.ts`; with `validation: false` it imports none. The generated files change for every project, so regenerate once. A models job skips a discovered file that has no `IModel` or `IObject` alias; a file that `models.sources` names must have an alias. A `models.sources` entry outside the root stops generation with RUNM1075. A generated file in a shared folder gives a warning; golem removes it only when an `outputs.json` entry of an older run records it. Delete them by hand, and delete any `.golem.lock` ([shared folder](docs/guide/shared-models.md)).
- A `golem.yaml` in a shared package, and a generated file beside a shared model file, give the warning RUNM1076 once for each run of `golem generate`, `golem check`, `golem build` and watch. Golem does not read the `golem.yaml` and does not use the generated file; generation continues. A `golem.yaml` with a `models` job below the `models.root` of another `golem.yaml` stops `golem generate` and `golem check` with RUNM1077, where the outer job used to skip its files. A shared package whose `package.json` `name` is absolute or has a `..` segment stops generation, because the name is a folder of `models.output`.

Each opens your project from `golem.yaml` (the `config` option, `GOLEM_CONFIG`, else `./golem.yaml`) and scans each file itself; with no `golem.yaml`, a TypeScript file outside `node_modules` fails. `golem check` and every build tool report a `parse<T>()` call that cannot be rewritten, with its file, its line and what to run. `@exprtlabs/golem/rewrite` exports `applyRewrites(text, rewrite, file?)`, which applies a list of text edits to a file and returns the code and its source map.

The message names the alias; move it into a model file. It was RUNM1053 for a field and RUNM1067 for a call.

Replace imports of `sdk/client.js`, `sdk/models.js`, `sdk/validation.js` and `sdk/client-runtime.js` with `sdk/index.js`, `sdk/models/<Name>.js` or `sdk/operations/<name>.js` ([generated files](docs/reference/generated-files.md)).
- **Breaking:** `__Projection<N>` schemas get stable names built from the type's shape. Add a named type alias to choose one.
- **Breaking:** install `@exprtlabs/golem` at or above the version the SDK was generated for, with the same major version. Generation commands fail before writing when it is older.
- **Breaking:** codec ids in generated files change. A hand-written model and an SDK model with the same name and shape no longer share an id.
- **Breaking:** the output inventory (`.golem/outputs.json`) records a `destination` and `destinationKind` for every file.
- Golem sorts names, keys and imports in generated files, `.golem/outputs.json` and `.golem/codec-keys.json` by code unit, so the same sources give byte-identical files under any machine locale. Regenerate once: an order that followed your locale (such as `maximum` before `maxLength`) changes. Field order feeds the codec id, so regenerating changes codec ids and SDK `_group-<hash>` file names once. For example, the fields `eTag` and `email` swap places.
- **Breaking:** the `models` output must lie inside the directory of the tsconfig that `golem.yaml` names, also through a folder link. Otherwise `golem.yaml` fails to load with an error that names the job, the resolved path and the directory. An SDK, a document or a generator output may lie anywhere.
- **Breaking:** golem stops and names the file, instead of deleting it, when a recorded file no longer holds its generated content and has no generator header. Move it or delete it yourself. A header names the generator package, followed by a space, a full stop or a line end, so a header of `foo-bar` is not a header of `foo`.
- Fixed: `golem watch` generates a new model file in any folder of the models root, also outside `src`.
- Fixed: Vite dev transforms a module again when a file that its serde type argument is re-exported through changes, also through an `export *` barrel.
- Fixed: `golem build` rewrites a side-effect import through a `paths` alias of a script file to the relative path of the emitted file.
- Fixed: golem resolves modules the same way on TypeScript 6 and 7. A `paths` alias without an extension resolves, a folder is not a module file, the `require` conditions of a package's `exports` apply to a CommonJS importer, and a module is resolved with the format of its importer.

### Package subpaths

- **Breaking:** eight subpaths of `@exprtlabs/golem` move under `internal/`: `emitter`, `schema`, `schema-graph`, `type-analysis`, `generated-paths`, `ts`, `validation-plan` and `validator-compiler` (for example `@exprtlabs/golem/internal/schema`). A path that starts with `internal/` may change in any release. The old names fail with `ERR_PACKAGE_PATH_NOT_EXPORTED`. Applications that use only the documented subpaths need no change.
- **Breaking:** `@exprtlabs/golem/cli` is removed. Run the `golem` command.
- `@exprtlabs/golem/validation-runtime` is a public subpath. Generated validators import it, and semver covers the names that they import. Do not import it in your code.

### Removed APIs (pre-1.0)

- `@exprtlabs/golem/validation`: `getModelValidator` (use `getValidator(model)`), `findCachedModelValidator`, `cacheModelValidator`, `validateGeneratedValue`, `preflightModelValidation`, `formatGeneratedIssues`, `evaluateModel`, `validationTagKey`, `validationTagSchemaDescriptor` and `validationTagGroups` (the first two tag helpers moved to `@exprtlabs/golem/schema`), and the structural validation helpers `fail`, `pushPath`, `popPath`, `enterActive`, `leaveActive`, `readOwn`, `runTag`, `runNestedModel`, `withNestedScope`, `childPath`, `continueStep`, `getProjection`, `rememberProjection`, `projectNestedModel`, `missingValidation` and `ensureNestedReady`. - `@exprtlabs/golem/errors`: `errorOwnerChain`, `invocationOwners`, `attachErrorOwners` and `readErrorOwners`.

- `@exprtlabs/golem/type-analysis`: `isIModelReference` (use `isModelDeclarationReference(checker, node)`). `@exprtlabs/golem/ts`: `readConfigFile`, `parseConfigFileTextToJson`, `flattenDiagnosticMessageText`, `createSourceFile`, `createProgram` (use `createProgramFromSources`) and the `errors` result of `parseJsonConfigFileContent`. `@exprtlabs/golem/emitter`: `generatedVariant` and `pruneNamedImport`.
