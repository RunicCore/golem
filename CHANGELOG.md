# Changelog

This file is the complete list of changes. The documentation site's
[release notes](docs/changelog.md) summarize the release.

## Migrating to 1.0

Every breaking change, one bullet per change, with the action to take:
[Migrating to 1.0](docs/migrating.md). Details for each package are
in the sections below.

## Release candidate

The first release candidate includes four independently installable packages:

| Package | Purpose |
| --- | --- |
| `@exprtlabs/golem-model` | Generate model bases from TypeScript declarations |
| `@exprtlabs/golem-openapi` | Generate typed clients and runtime models from OpenAPI |
| `@exprtlabs/golem-ts-openapi` | Generate OpenAPI from NestJS controllers |
| `@exprtlabs/golem` | Shared CLI, model runtime, validation and serialization |

### Models

- **Breaking:** generated names keep the exact type alias; golem no longer drops a leading `T` or a trailing `Model`. `type TPayment = IModel<…>` generates `TPaymentBaseModel`, `TPaymentFields`, `TPaymentJSON` and `TPaymentInit` (it was `PaymentBase`, `PaymentFields`, `PaymentJSON` and `PaymentInit`), and its functions use the alias, such as `parseTPayment`. `type Payment = IModel<…>` generates `PaymentBaseModel`; `type TPermissionModel = IModel<…>` generates `TPermissionModelBaseModel`. The base suffix is `BaseModel` for every model. Names of derived types keep the alias (`TPaymentBilling`, `TMerchantOmitId`; they were `PaymentBilling`, `MerchantOmitId`). Regenerate and update `extends`.
- **Breaking:** your class links to its model through `extends <Alias>BaseModel`, not through its name, so `class PurchaseOrder extends TOrderBaseModel` works. Every exported class of the model's file that extends the generated base directly links to the model and gets its own plugin key, so `parse<AdminPayment>` builds an `AdminPayment`; a subclass of a linked class does not link. A model with one linked class uses it as its default class. A model with several has no default class: decoding uses the generated base unless the type names a class, and a field typed by a class builds that class.
- **Breaking:** a model file no longer exports the codec functions of derived types (an `Omit`, `Pick` or alias of a model, such as `parseTMerchantOmitId`). Other generated files reach them by codec id; use the declared model's functions.
- **Breaking:** a `TSerde` or `TValidation` function declared in a `*.model.ts` file is a generation error (RUNM1065). It closed an import cycle with the `.model.generated.ts` file that crashed start-up whenever that file loaded first. Move the function to its own module.
- Several `TValidation` predicates on one value run in a fixed order, not in written order, so types that differ only in that order generate the same code.
- `@exprtlabs/golem/temporal` adds Temporal field types (`TemporalInstant`, `TemporalPlainDate`, …) with ISO 8601 wire strings and nanosecond precision.
- Type aliases of tags accept type parameters as tag arguments, such as `type Varchar<N extends number> = string & MaxLength<N>`.
- The order of constraint tags (`MinLength<2> & MaxLength<4>`) no longer changes a model's codec id.
- A tag argument that depends on a type parameter and sits behind another alias of the tag fails with `RUNM1064`, which names the tag. It was reported as a repeated tag (`RUNM1062`).
- Tag aliases and `TSerde`/`TValidation` functions can come from an installed package; generated files import them through the package's `exports`.
- A malformed `package.json` met while resolving a package import fails with an error that names the file and keeps the parse error as its cause.
- A package's `exports` are read as Node reads them for an ES module import: the most specific pattern key wins, a `null` target or condition excludes the file (RUNM1060), the first matching condition among `types`, `import`, `node` and `default` decides, and other conditions are skipped.
- **Breaking:** a `TSerde`/`TValidation` function in another package, including a sibling workspace package, is imported by its package name, so that package must export the file (RUNM1060). Earlier releases wrote a relative path into the other package. Add an `exports` entry for the codec file.
- A `TSerde` field can hold a class instance, such as `Uint8Array`, or a `bigint`.
- A class held by a `TSerde` field is imported under its exported name, including `export { A as B }` and default exports, and under a generated alias, so two classes with the same name from different modules both compile. An anonymous, unexported, generic or `declare module` class fails with `RUNM1063` instead of producing a broken import.
- `IModel` / `IObject` `exact` defaults to `true`. Opt out with `{ exact: false }`.
- Synchronous `parse` / `stringify` convert JSON text; `fromWireFormat` /
  `toWireFormat` convert the object plane. Type-only targets fill a plain
  IObject; class targets construct that class.
- `toWireFormat<T>` returns `WireFormat<T>` (exported from `@exprtlabs/golem/serde` and `/model`), which equals the generated `XJSON` type, instead of `unknown`; drop `as XJSON` casts. Generated `toWireFormatX` functions and `ObjectCodec.toWireFormat` report the same type.
- Validated conversion checks each rule once. `parse` / `fromWireFormat` check the full JSON, then only converted values and model `TValidation` rules; `stringify` / `toWireFormat` check the full model, then only the JSON written for converted fields. `IObject` `parse` now enforces those model rules too. Validation contexts resolve by reference (`resolve(reference, mode)`, with `Id`, `Id#wire`, `Id#model-only`, `Id#wire-only`); `registerCodecSchemas` fills an engine.
- `toWireFormat` and `encodeGeneratedModel` omit an optional field whose value is `undefined`, as `stringify` and `JSON.stringify` do. A nested plain object without a projection keeps an `undefined` key you set on it.
- Decoding nested models is faster: model fields are assigned directly unless the class or its prototype chain already has a property of that name (inherited setters are still never invoked).
- **Breaking:** decoding no longer clones the input first. Getters run once per declared property, `fromWireFormat` and `parse` still copy objects, maps and arrays, values typed `unknown` or `any` (including the undeclared properties of an open object) are carried by reference, `decodeGeneratedModel` copies nothing (fields without conversion are the input's own values), and a cycle is reported when conversion reaches it rather than before any decoder runs. `cloneConversionInput` is removed from `@exprtlabs/golem/conversion`. Regenerate.
- Generated `XJSON` and `XFields` types keep `readonly` from `Readonly<>` and other mapped types, and drop it under `-readonly`.
- Nested model conversion preserves model instances. Projected types such as `Pick` and `Omit` produce plain objects with the selected fields and keep their field conversion and constraints. `IModel` exposes declared field keys to TypeScript utilities.
- Root model unions such as `IModel<TEmail | TPhone>` are rejected (`RUNM1052`); keep the union in a field.
- Built-in constraint tags generate validation. `TValidation` references a custom predicate; `TSerde` references a pair of conversion functions.
- Serde validates by default when validation is generated. It stops at the first issue and leaves displayed field errors unchanged. `ObjectCodec.validate` is the wire plane.
- **Breaking:** `validateInstance(model)` and `getValidator(model).validate()` stop at the first issue by default, like serde. Pass `{ failFast: false }` to collect every field error (for example in a form).
- `getValidator(model)` and `validateInstance(model)` accept a model registered without a generation profile and validate its codec, schema or custom rules (previously they threw); with none of these, validation throws `ValidationUnavailable`. A generated model that disables validation, or enables it without conversion and codec metadata, still throws `ValidationUnavailable`.
- **Breaking:** decoding a `Date` field accepts only a parsable date-time string (or an existing `Date`); anything else throws a `LibError` of kind `deserialization` (`causedByInput: true`) instead of producing an invalid `Date`.
- `LibError.causedByInput` marks failures caused by the rejected value: validation, invalid JSON, an unknown discriminator tag, an unparsable date, cyclic input, and a non-object where a generated model expects an object. `NestModelInterceptor` answers those with HTTP 400; a throwing application converter (including a `TSerde` decoder), a throwing custom validation rule or message formatter, a failing validation engine, and missing generated metadata remain HTTP 500.
- Optional MobX integration includes nested generated models.
- Discriminated unions may use string, number or boolean tags and several tag values per variant. **Breaking:** serializing or initializing a union value whose tag is unknown or missing throws a `LibError` (previously an unknown tag serialized as `null` or passed through). An instance without its tag is written with its variant's first tag value.
- An unknown or missing tag in decoded input is an input error (`causedByInput: true`, HTTP 400 in Nest). With validation enabled, `parse` and `fromWireFormat` report it as kind `validation`; with validation disabled (profile `validation: false` or `{ validate: false }`) and in constructors, it is kind `deserialization` (`Unknown <tag> discriminator value`). Encoding an instance whose tag is unknown or contradicts its variant class throws kind `serialization` (`causedByInput: false`).
- TypeScript 6.0 is supported for generation, with TypeScript 7. Golem selects the backend from the project's installed `typescript` (resolved from `GOLEM_TYPESCRIPT_ROOT`, else the current directory, falling back to its own): `>=6.0.0 <7` or `>=7.0.0 <8`. Any other version fails at load with `golem supports TypeScript 6.0+ and 7.x; found <version> at <path>.` TypeScript 5 is unsupported.
- The `typescript` peer range of `@exprtlabs/golem`, `@exprtlabs/golem-model` and `@exprtlabs/golem-ts-openapi` is `>=6.0.0 <8`. Generated output is byte-identical on 6 and 7, and a test lane enforces it.
- `parse<T>` / `stringify<T>` and the other generic serde calls work on TypeScript 6 and 7: golem's own rewrite replaces `ttsc`.
- **Breaking:** `@exprtlabs/golem/ts` publishes Golem-owned types narrowed to what Golem uses. Its type declarations no longer reference `typescript`; `Program`, `CompilerOptions` (now an untyped options map) and `Diagnostic` are narrower; the `API` class and the TypeScript 7 process-client types are no longer exported from it. It exports only the value names Golem uses.
- Union members in generated types and schemas are emitted in a fixed canonical order (code-unit order of their canonical key, independent of compiler and locale), so regenerating changes member order and codec ids once.
- On TypeScript 7, generation type-checks newly generated files before writing them. Previously new files were skipped, so a run that produced non-compiling output could succeed; it now fails with the compiler diagnostic. The check uses the project tsconfig's file set and checks only the job's own generated files, so sibling model folders under one tsconfig no longer interfere.
- A decode error inside a tuple item, or inside an array item of a scalar-or-array union, now ends its path with the item index, such as `['dated', 2]` or `['when', 1]`. It named the field only.
- A scalar value of a scalar-or-array union such as `string | Date[]` now converts by its own type. Before, golem converted it like an array item, so a valid string failed as a bad date (HTTP 400), a number string such as `'12'` became a `Date`, and encoding the string threw. A scalar variant that needs a conversion must be the only scalar variant, as in `Token | Token[]`; a union such as `Token | number | Token[]` is now rejected at generation, as `Date | Date[]` already is.
- A scalar-or-array union may hold one tuple instead of an array, such as `string | [Date]` or `oneOf` of `string` and a `prefixItems` tuple. The tuple converts by item, with the item index in a decode error path, and the scalar converts as in `string | Date[]`. `string | [Date]` was rejected as ambiguous; a union whose tuple items need no conversion, such as `string | [string]`, already generated.

### OpenAPI

- Components with alike names, such as `Payment`, `TPayment` and `PaymentModel`, no longer collide: each is its own model with its own SDK class, including when they reference each other. Two components whose names become one after file-name or identifier cleanup still fail generation with a message that names both.
- **Breaking:** an OpenAPI document built from TypeScript models names a model that has a class by the class (`class Payment extends TPaymentBaseModel` gives `components.schemas.Payment`), and a model without a class, with several classes, or an `IObject`, by its exact alias (`TPayment`); it was the alias without its `T`. `@ApiSchema({ name })` still sets the name. Equal names with identical schemas share one component. Equal names with different schemas are qualified by where the models are declared: `<directory>.<Name>`, such as `orders.Payment` and `billing.Payment`, where `<directory>` is the shortest trailing run of the file's directory segments, relative to the project root and joined with `.`, that tells them apart; models in one directory add the file name without `.model.ts` or `.ts`, as in `billing.payment.Payment` and `billing.refund.Payment`. The SDK that `@exprtlabs/golem-openapi` generates from a document keeps its class and type names.
- An OpenAPI job's `dates: temporal` maps `format: date-time`, `date` and `duration` to Temporal types.
- **Breaking:** `ClientRuntime` no longer has `getOperationValidators`, `validateOperationInput`, `responseValidator` or `assertValid`. `@exprtlabs/golem/validation` exports `operationValidators`, `validateOperationInput` and `responseCheck`, and `readResponse` takes an optional response check in place of the validators. An SDK generated with validation off no longer bundles the validation runner. Regenerate the SDK.
- **Breaking:** a generated SDK no longer contains dead schema code. No SDK writes `schemas.ts`, the SDK-wide `validators.generated.js` (with its `.d.ts` and notices file) or `validation-engine.ts`; it validates with the validator module of each operation and model group. `schemaDialect`, `schemaNames`, `operationNames`, `operationResponseSchemaEntries`, the reference helpers, `createRuntimeValidators` and `createOperationRuntimeValidators` are gone. The client's `operationValidators` option is keyed by the client's own operation names (previously inbound operations were included). Files in `validation-schemas/` export only `schema`, and `model-manifest.json` model entries no longer carry `validation`. Regenerate the SDK.
- **Breaking:** `@exprtlabs/golem/validation` no longer exports `createRegistryValidators`, `createRegistryOperationValidators`, `SchemaRegistryData` or `createStaticValidationEngine` (generated code no longer uses it). Pass validators through the client's `operationValidators` option, or let the client resolve them.
- Client methods create reusable operation objects. `.execute(input, options)` sends the request.
- Clients support authentication, body codecs, cancellation and supported streaming responses.
- With MobX enabled, each operation exposes observable `loading`. Concurrent executions are allowed and produce a warning.
- A local `$ref` into a folder whose name starts with `..`, such as `./..shared/pet.yaml`, loads. Only a reference that leaves the input directory is rejected.
- Controller generation reads NestJS routes and TypeScript types without starting the application.
- Controller decorator metadata is read from literals, `const` declarations, enum members and whole enums, `const` objects, spreads and string templates. **Breaking:** a structural option (`type`, `enum`, `schema`, `format`, bounds, `required`, `nullable`, tags, security, status) that is not a compile-time constant fails generation with `NEST1504`; a non-constant documentation option (`description`, `summary`, `title`, `example`, `externalDocs`) is dropped with a `NEST1504` warning. `let` and `var` route constants are rejected.
- `getSchemaPath()` and `refs()` become component references and honor `@ApiSchema({ name })`. `@ApiProperty` accepts `type: 'integer'`, `Date` and enums, applies to array and optional nested DTOs, and keeps metadata for every nested property.
- Inherited routes from generic and mixin base controllers use the derived class's type arguments. `Observable<T>` returns are unwrapped like `Promise<T>`.
- **Breaking:** `@exprtlabs/golem-ts-openapi` declares `typescript` (`>=6.0.0 <8`) as a peer dependency instead of a dependency; install it in the consuming project.
- **Breaking:** parameters decorated with `@Header()`, `@Cookie()`, `@Cookies()` or `ApiCookie` are no longer read as OpenAPI parameters. None is a `@nestjs/common` parameter decorator (`@Header()` sets a response header), and `@nestjs/swagger` exports no `ApiCookie`. Use `@Headers('name')` for request headers. No supported decorator produces a cookie parameter; `@ApiCookieAuth()` documents cookie authentication as a security scheme.
- Emitted paths and object keys are ordered by code unit instead of the host locale, so documents are identical on every machine.
- **Breaking:** controller security follows `@nestjs/swagger`: class-level security (including base controllers) and method-level security are concatenated; previously a method requirement replaced the class requirement. Class `@ApiTags` and security are also read from base controllers, including a decorated base wrapped by a mixin (`extends Timestamped(BaseController)`).
- **Breaking:** an `@ApiQuery()` or `@ApiParam()` without `required` marks its parameter required, including a declared optional `@Query('x') x?`, matching `@nestjs/swagger`; set `required: false` to keep it optional. A `@Query('limit') limit = 20` parameter with a default value is optional.
- **Breaking:** two parameters with the same name and location in one operation fail with `NEST1312`. In OpenAPI 3.2, a whole `@Query()` object (a `querystring` parameter) beside `@Query('name')`, an `@ApiQuery()` for a name that is not one of its fields, or a second `@Query()` object fails with `NEST1107`. An `@ApiQuery()` for one of its fields documents that field in the querystring schema, as OpenAPI 3.1 documents the flattened parameter.
- **Breaking:** `@Search`, `@QueryMethod`, WebDAV method decorators and `@RequestMapping` with `RequestMethod.ALL`, `SEARCH`, `QUERY` or a WebDAV method fail with `NEST1201`, as `@All`, `@Sse` and `@Redirect` already did, regardless of decorator order. `@RequestMapping` with an OpenAPI method is supported. Endpoints excluded with `@ApiExcludeEndpoint()` or `@ApiOperation({ hidden: true })` are skipped before their route is checked.
- **Breaking:** route paths with wildcards (`*`, `*splat`), regular-expression parameters (`:id(\d+)`) or quoted names fail with `NEST1207` instead of producing invalid paths. Optional segments (`:id?`, `{/:id}`) expand into one operation per path, with `__path_N` operationId suffixes; the paths without the segment omit its `@Param()`.
- `@ApiQuery`, `@ApiParam` and `@ApiHeader` overrides apply to the parameter with the same name *and* location. `@Header(name, value)` is documented as a header of the success response; `@Header('Content-Type', type)` sets the success response media type instead. `VERSION_NEUTRAL` is accepted in `@Controller({ version })`.
- An explicit Swagger `schema` that composes components (`$ref`, `oneOf`, `anyOf`, `allOf`, for example with `getSchemaPath()`) replaces the inline schema of an ordinary DTO response or body instead of being emitted beside it. `@ApiProperty({ enum, enumName })` emits one `components.schemas.<enumName>` and references it.
- `NEST1503` conflict messages name the schema keyword path and both values, and say which TypeScript declaration to change.
- A whole-object `@Query()` model decodes query strings to its declared number, integer, boolean, literal and array fields before validation.
- An OpenAPI `discriminator` on a `oneOf`/`anyOf` of `allOf` variant models selects the variant through explicit (reference or component name) and implicit mappings, including several values for one variant. Variant models keep their declared tag type. A discriminator on a base schema without `oneOf`/`anyOf` is reported as unsupported (see the OpenAPI support matrix).
- **Breaking:** every variant of a discriminated union must declare the discriminator property; generation rejects a variant that does not.
- **Breaking:** a variant shared by two discriminated unions now gives neither union a model class, with a generation warning; values typed by those unions still decode to the variant models. Previously the result depended on component declaration order.
- **Breaking:** `@exprtlabs/golem-openapi/generator` no longer exports `generateClient`, `generateInbound`, `generateLinks`, `generateSchemas`, `generateTypes`, `generateValidation`, `generatedFiles` or `generateModelManifest`; use `generate` or `writeSdk`.
- **Breaking:** decoding or initializing a union model with an unknown discriminator value throws a `LibError` (previously a `TypeError`): kind `validation` when the call validates, otherwise `deserialization`, as described under Models.
- A discriminated `anyOf` of component models now generates an abstract union model class, as `oneOf` does; without a discriminator, `anyOf` is unchanged.
- **Breaking:** an implicit discriminator value is the raw component name (`cat`), as OpenAPI specifies, not the generated type name (`Cat`). Generation warns when the two differ.
- **Breaking:** in OpenAPI 3.0, `nullable: true` admits `null` only beside `type` (OAS 3.0.3). Without `type`, including a `$ref` sibling or `allOf` wrapper, types, models and runtime schemas no longer admit `null`. In 3.1 and 3.2 documents `nullable` is ignored; use `type: [..., 'null']`.
- Reserved-word or client-member operation names (`delete`, `constructor`) receive a `_` suffix with a generation warning; operation modules that differ only by letter case are rejected.
- Component schemas named `Array` or `Blob` no longer shadow generated array and binary types.
- **Breaking:** a response the operation declares without content now resolves with an undefined body and cancels any body the server sends (previously a content type on it failed). An undeclared status or media type cancels the body and throws a `LibError` of the new kind `response` (`LibErrorKind.Response`) carrying `operation`, `status`, `headers` and `contentType`; `is<Client>UndeclaredResponseError` recognizes it (previously a plain `Error`).
- **Breaking:** `allowReserved` query values keep `#`, `[`, `]`, `&` and `+` percent-encoded and pass existing `%XX` escapes through unchanged (previously those characters were sent literally and `%` was re-encoded).
- Security requirements `[{}, {...}]` send configured credentials; the empty requirement is only the fallback. Basic credentials are UTF-8 encoded, and a username containing `:` is rejected (RFC 7617). Nested `deepObject` values serialize as `name[a][b]=v`; nested `null` and `undefined` members are skipped. Server-sent events no longer dispatch early on a CRLF split across chunks, an unterminated event at the end of the stream is discarded, and a data-less event no longer passes its `event` type to the next event.
- Cookie parameters and cookie API keys produce the `OPENAPI_BROWSER_COOKIE` generation warning: browsers do not let scripts set the Cookie header. Node behavior is unchanged.
- A caller-supplied `fetchImpl` is called without a receiver (`this` is `undefined`, previously the client), so a native browser `fetch` works.
- Generated TypeScript writes arrays as `T[]` instead of `Array<T>`.
- Fixed: an `allOf` variant decodes and validates fields it inherits from a referenced base, such as a `date-time` field decoded to `Date`, and a discriminated union's wire validation uses each variant's wire schema (a valid `createdAt` was rejected by `fromWireFormat`).
- Fixed: component names containing `~`, `/` or spaces generate type names, registry ids and discriminator mappings correctly (for example `a~cat` produced an undefined type `A0cat`).
- A non-object where a generated model expects an object is rejected as input (`LibError` of kind `deserialization`, `causedByInput`, HTTP 400 in Nest) instead of a `TypeError`.
- **Breaking:** OpenAPI 3.0 documents are rejected; convert them to 3.1 or 3.2.
- **Breaking:** `@redocly/openapi-core` is no longer a dependency. Golem resolves `$ref`s and validates documents itself.
- **Breaking:** a schema pulled in from another file is named after its path (`schemas/user.json` → `schemas.user`, model `SchemasUser`) instead of its file name with a numeric suffix. A root component that is only a `$ref` to an external file keeps its own name; a root component with a `$ref` plus other keys is not an alias, so its target still gets the path-based name and can collide with the root name. A name clash now fails generation, naming both locations.
- **Breaking:** an implicit discriminator value for a schema from another file is now its path-based component name (for example `schemas.dog`). Use an explicit `mapping`, or a root alias, to keep a chosen value.
- **Breaking:** the `spec-ref-siblings`, `path-not-include-query`, and `nullable-type-sibling` validation rules are gone; error lines name the file that contains the problem.
- A discriminator `mapping` value in another file that is a bare name no root component declares fails generation with a message naming the mapping and its file; use `#/components/schemas/Dog` or a root alias. Documented as unsupported.
- `no-unresolved-refs` reports a discriminator `mapping` pointer that resolves to nothing, at the location in the file that contains it. Previously it failed later as a variant error.
- A generation error that names a component (a discriminator mapping, a generated name collision, a field name, an unsupported HTTP authentication scheme) now adds where it is declared, such as `schema "pets.Pet" (pets.json#/Pet)`, also for a single file (`api.json#/components/schemas/Pet`). The field-name error ends with `(at pets.json#)`, not `(at #/components/schemas/pets.Pet)`. `writeSdk` takes an optional `locate` to do the same; without it messages are unchanged.
- A JSON Schema `$id` declared twice, also across files, is reported as a validation error (`schema-id-unique`) that names both locations. It threw an unformatted `duplicate JSON Schema $id` error.
- An `x-` key under `paths` or `webhooks` is an extension, not a path item: validation and schema generation skip it.
- **Breaking:** `collectLocalReferenceInputs` from `@exprtlabs/golem-openapi/generator` now returns a `Promise`.
- A name in the `required` list of any `allOf` member is required in the generated TypeScript type wherever a member declares the property, as the validator already required it (`allOf: [{ $ref: Pet }, { required: [name] }]` makes `name` required in that type; `Pet` itself is unchanged), including inside the `oneOf` and `anyOf` branches of an `allOf` member, and a schema's own `required` names that it does not declare itself apply to its own `oneOf` and `anyOf` branches.
- Fixed: a generated model's `prefixItems` tuple field converts each item by its own schema. With `prefixItems: [{ type: string }]` and `items: { type: string, format: date-time }`, the first item stays a string and the rest decode to `Date`; before, every item was converted as a `Date`, so the string failed to decode. The field type is the tuple (`[] | [string] | [string, ...Date[]]`), not `Date[]`, and a tuple with `items: false` converts its items too. The type of a tuple field changes with its items: `[string]` becomes `[Date]` for a `date-time` item, and `[Types.Pet]` becomes `[PetModel]` for a model item. An ambiguous union inside a prefix item now fails generation; it used to generate without conversion.
- Fixed: a generated model's array or `prefixItems` tuple field converts its items by its own schema when its `allOf` members only add constraints or a description, such as `allOf: [{ minItems: 1 }]`. Before, `items: { type: string, format: date-time }` was typed `Date[]` but the values stayed strings, so `.getTime()` threw at runtime. When exactly one `allOf` member declares the array and converts its items, that member decides both the type and the conversion. A tuple with such an `allOf` is now typed by its items too (`[] | [string]` becomes `[] | [Date]` for a `date-time` item).
- Fixed: a generated model's array or `prefixItems` tuple field with no `type`, or with `type: [array, null]`, converts and is typed like `type: array`. Before, `items: { type: string, format: date-time }` beside `type: [array, null]` stayed `string[] | null`; now it decodes to `Date[] | null`, and `null` stays `null`. The same holds for such a schema as a `oneOf` branch beside a scalar.
- Fixed: a generated model's object or `oneOf` field converts by its own `properties` or `oneOf` when its `allOf` members only add constraints or a description, such as `allOf: [{ minProperties: 1 }]`. Before, `properties: { at: { type: string, format: date-time } }` was typed `{ at?: Date }` but `at` stayed a string, so `.getTime()` threw at runtime; the same held for a `oneOf` with a `date-time` branch. The constraints still apply. When an `allOf` member declares the object itself, that member decides the conversion.
- Fixed: a generated model's inline nullable object field (`type: [object, null]` with `properties` or `additionalProperties`) admits `null` and is typed with `| null`. Before, validation rejected `null` and the type was the object alone, `{ at?: Date }`. The same holds when its `allOf` members only add constraints, such as `allOf: [{ minProperties: 1 }]`; an empty object still fails the constraint.
- Fixed: a generated model field that references a nullable component object (`Pet: { type: [object, null] }`, `pet: { $ref: Pet }`) is typed `PetModel | null` and its validator admits `null`. Before, the field type was `PetModel` and validation rejected `null` with `PetModel expected an object`.
- Fixed: a generated model's inline object field with its own `properties` and an `allOf` member that declares properties is typed and converted from both. With `properties: { at: date-time }` and `allOf: [{ properties: { b: date-time } }]`, the type is `{ at?: Date } & { b?: Date }`, and `at` and `b` both decode to `Date`. Before, the type held only `at` while the conversion read only `b`, so `at` stayed a string.

See [OpenAPI client support](docs/reference/openapi-support.md) for supported versions and contract limitations.

### Validation

- **Breaking:** Ajv is removed. golem validates with validators it generates, in one mode; `ajv` and `ajv-formats` are no longer peer or optional dependencies. The `@exprtlabs/golem/ajv` and `@exprtlabs/golem/ajv-tooling` subpaths, `OpenApiAjvOptions`, `createOpenApiAjvEngine`, `createOpenApiSyncAjvEngine`, `configureModelValidationEngine` and `registerModelValidationEngineFactory` are removed.
- **Breaking:** `ajvStandalone` is removed from `golem.yaml` and `GolemProfile`; the key is now an unknown-key error.
- `golem.yaml` gains `unknownFormats: warn | error` (default `warn`) for a schema `format` that golem does not check. golem checks `byte`, `json-pointer` and `relative-json-pointer`; Ajv also checked `uri-template`, `url`, `iso-time` and `iso-date-time`, which now report a warning and are not checked.
- **Breaking:** validators are written as TypeScript: `models.validators.generated.ts`, `_<group>.validators.generated.ts` and `operations/<name>.validators.generated.ts`, with no notices file. The next generate deletes the old `.js`, `.d.ts` and `.NOTICES.txt` outputs.
- **Breaking:** issue codes describe the kind of failure (`type`, `required`, `tooSmall`, `tooBig`, `literal`, `unknownKey`, `invalidKey`, `union`, `instance`, `pattern`, `format`, `multipleOf`, `unique`, `not`, `never`, `custom`) with typed fields. The per-keyword codes and `params` are gone, and the default English messages changed ([mapping](docs/migrating.md#issues)). `IssueCode` is a string-union type, no longer an enum: `IssueCode.Required` no longer compiles, so use the string codes. The HTTP 400 body of a NestJS application carries the new issue shape (no `params`); update clients that read it.
- **Breaking:** `ValidationRuleResult` takes `{ message }` only; an issue from a rule has the code `custom`. `ModelValidationContext` is `{ resolve }`; `engine` is removed.
- **Breaking:** `ClientRuntime` loses `defaults`, `createValidationEngine` and `validationEngine`. A client's `operationValidators` override is a `Validator`, `(value, all)` returning an array of issues; any other result throws `TypeError`. `ValidationResult` is `{ valid, issues }`, and `validateWith` takes `all`.
- A property whose value is `undefined` counts as absent. The `source` of an issue from a nested model is the source of the model that holds it.
- **Breaking:** an SDK generated by an older release, without `validationSchemaClosure` in its `model-manifest.json`, fails generation in every project that uses its models, with validation on or off. Regenerate the SDK.
- **Breaking:** `$dynamicRef` and `$dynamicAnchor` in an external OpenAPI document fail generation with `VALIDATE_UNSUPPORTED_KEYWORD`.

### Generation

- **Breaking:** `ttsc` and the Go plugin are removed, with the `@exprtlabs/golem/ttsc-plugin` and `@exprtlabs/golem-ts-openapi/ttsc-plugin` subpaths and the `ttsc` peer dependency of every package. Replace `ttsc` with `golem build`, the golem Vite or esbuild plugin (`@exprtlabs/golem/vite`, `@exprtlabs/golem/esbuild`), or the Node loader (`node --import @exprtlabs/golem/register`); delete the `plugins` entry from `tsconfig.json`; its `"nest": true` option is a `controllers` job in `golem.yaml`, and its `"serde": false` option has no replacement. `golem build` generates first, so nothing has to run before a build.
- **Breaking:** `golem.yaml` gains the `tsconfig:` key (default `tsconfig.json` beside it) and is the entry point for `golem build`. One `golem.yaml` serves one tsconfig: the `root` of a `models` or `controllers` job must lie inside its directory, and the tsconfig must be the one the job finds.
- **Breaking:** the codec-key table of your own models moves from `src/generated/models/iobject-plugin-keys.ts` to `.golem/codec-keys.json` in the directory of `golem.yaml`. The `model-manifest.json` of an SDK gains a `codecId` for each entry of `models`, and the SDK stops writing `iobject-plugin-keys.ts`. Tables of SDKs generated before this release are still read. Regenerate your SDKs.
- Generated files need not be committed. Ignore the generated files and `.golem/` together, or commit the generated files with `.golem/outputs.json` and `.golem/codec-keys.json`. Always ignore `.golem/jobs.json`, which records what each job read, and `.golem/build/`. A second `golem generate` or `golem build` with no change runs no job.
- `models.suffixes` and `controllers[].suffixes` choose the file endings that mark a model or a controller (`.mts` and `.cts` too). A generated file puts `.generated` before the final extension of its source, so `order.entity.ts` gets `order.entity.generated.ts`.
- Generation stops only on a type error in the models job's own model sources and in the files it writes. A type error in another handwritten file no longer stops `golem generate`; `tsc` and `golem build` report it. Editing any project source runs the models job again, because it reads the whole project.
- Known limits: a NestJS app through the Node loader needs a second loader that compiles decorators, registered after golem's. With `preserveSymlinks`, a `parse<T>()` call in a symlinked workspace package fails at run time, not in the host. A generator that lists `watchInputs` it never announced through `onInput` runs on every build.
- `golem build [--config golem.yaml] [-p tsconfig.build.json] [--watch] [tsc arguments...]` generates first, type-checks your original sources with your TypeScript, then emits JavaScript with the generic serde calls rewritten from a staged copy. Like `tsc`, it emits after type errors unless `noEmitOnError` is set. It passes every other argument to `tsc`, and `-w` means `--watch`. It rejects the arguments it sets itself (`--noCheck`, `--noEmit`, `--emitDeclarationOnly`, `--tsBuildInfoFile`, `--incremental`, `--outDir`, `--listEmittedFiles`, `--rootDir`, `--baseUrl`, `--composite`, `--outFile`, `--declarationDir`, `--sourceRoot`, `--mapRoot`, `--inlineSourceMap` and `--inlineSources`) and says what to set in the tsconfig. It rejects a missing `outDir`, project references (`-b`), `outFile`, `rootDirs`, `inlineSourceMap` and `sourceRoot`. Its state lives in `.golem/build/<tsconfig name>/`.
- `golem build`, `golem check`, the Vite and esbuild plugins and the Node loader accept every file the tsconfig includes, as `tsc` does, including files outside its directory such as `../shared/*.ts`, and rewrite the `parse<T>()` calls in them. The diagnostic RUNM1070 no longer exists.
- **Breaking:** a shared folder works like an installed package. A models job generates only for a model file whose real path is inside `models.root`; golem follows folder links to find the real path. Golem writes nothing into a folder outside the root and takes no lock there. A plain type of an outside folder is a field type of an app model, and its constraints apply. A `TSerde` or `TValidation` function of an outside folder works in an app model; the ids of functions outside the root are relative to the root. The layer `models.generated.ts`, the specifier `#golem-models` and the lock `.golem.lock` are gone, so a tool outside golem needs no `imports` entry, alias or `paths` entry. Each `<name>.model.generated.ts` fixes the profile of the app, holds its own schemas, and imports only its own validators, by relative path, from `models.validators.generated.ts`; with `validation: false` it imports none. The generated files change for every project, so regenerate once. A models job skips a discovered file that has no `IModel` or `IObject` alias, and a file that the `models` job of a `golem.yaml` below the root covers; a file that `models.sources` names must have an alias. A `models.sources` entry outside the root stops generation with RUNM1075. Golem leaves old generated files in a shared folder, and the files of old shared entries in `.golem/outputs.json`, on disk. Delete them by hand, and delete any `.golem.lock` ([shared folder](docs/reference/config.md#a-folder-shared-by-several-apps)).
- The Node loader, the Vite plugin and the esbuild plugin are public subpaths. Each opens your project from `golem.yaml` (the `config` option, `GOLEM_CONFIG`, else `./golem.yaml`) and scans each file itself; with no `golem.yaml`, a TypeScript file outside `node_modules` fails. `golem check` and every host report a `parse<T>()` call that cannot be rewritten, with its file, its line and what to run. `@exprtlabs/golem/rewrite` exports `applyRewrites(text, rewrite, file?)`, which applies a list of text edits to a file and returns the code and its source map.
- A model field that names an `IModel` or `IObject` alias that is not a model of the app stops generation with RUNM1074. A call of `stringify`, `parse`, `validate`, `assertValue`, `toWireFormat` or `fromWireFormat` that names such an alias gets the same error from `golem check`, `golem build` and the hosts, not from generation. The message names the model and gives one of three reasons: the model is in `node_modules`, the model is outside `models.root`, or the model belongs to the `models` job of a `golem.yaml` below the root. For the first two, declare the model in your own source over the plain type. It was RUNM1053 for a field and RUNM1067 for a call.
- Fix: a TypeScript 7 watch no longer loses a `tsconfig` edit made while a program was being built.
- Fix: `golem --help`, and `generate` and `check` on a `golem.yaml` with no `models` or `controllers` job, run in a project without TypeScript; only commands that read your types load the compiler.
- **Breaking:** the packages, CLI and files are renamed to golem. `@exprtlabs/codegen` is `@exprtlabs/golem`, `@exprtlabs/model-codegen` is `@exprtlabs/golem-model`, `@exprtlabs/openapi-to-ts` is `@exprtlabs/golem-openapi` and `@exprtlabs/ts-to-openapi` is `@exprtlabs/golem-ts-openapi`; subpaths are unchanged. The CLI is `golem`, the config file `golem.yaml` and the inventory directory `.golem/`. Generator-API types are renamed from `Codegen*` to `Golem*` (for example `GolemProvider`, `GolemProfile`), and generated internal names from `__runic*` to `__golem*`. Rename `runic-codegen.yaml` to `golem.yaml`, delete `.runic-codegen/` and run `npx golem generate`.
- `generators` jobs run generators from installed packages before the built-in jobs.
- A `generators` package is a third-party package: its version is not compared with `@exprtlabs/golem`, and naming a built-in package (`@exprtlabs/golem-model`, `-openapi`, `-ts-openapi`) is a configuration error that names the `models`, `openapi` or `controllers` job to use.
- Generated files are replaced on regeneration; handwritten behavior belongs in source declarations and subclasses.
- `generate` and `check` stop with an error instead of replacing a file at an output path that golem did not generate.
- Identical output keeps its modification time. `check` reports drift without writing files.
- Watch regenerates when a model imports a project file outside its job root.
- Model generation analyzes each model once per job, and a `.model.generated.ts` file emits code only for the models its source declares; models from other sources are referenced by codec id and their generated files are imported. Generation time and output size now grow linearly with chains of referencing models (80 chained models: 1.4 s and 4.8 MB, previously 36 s and 284 MB), and models that reference each other across files load in either import order. The generated files of referenced models export internal `__golem*` helpers and an `XInit` type; do not import the helpers directly.
- Validation defaults to on and MobX to off. `allowAny` defaults to false and can be overridden per model.
- Tooling requires Node.js 22.15 or newer.
- **Breaking:** `@exprtlabs/golem-model` declares `typescript` (`>=6.0.0 <8`) as a peer dependency instead of a dependency, like `@exprtlabs/golem-ts-openapi`; install it in the consuming project.
- Packages no longer publish source maps, which referenced unpublished TypeScript sources.
- **Breaking:** regenerate after upgrading. SDKs and OpenAPI documents change.
- **Breaking:** the SDK no longer writes `validation.ts`, `client-runtime.ts` or `models.ts`, and `client.ts` is internal. The code the SDK used to carry now lives in `@exprtlabs/golem/client` and `@exprtlabs/golem/validation`. Replace imports of `sdk/client.js`, `sdk/models.js`, `sdk/validation.js` and `sdk/client-runtime.js` with `sdk/index.js`, `sdk/models/<Name>.js` or `sdk/operations/<name>.js` ([generated files](docs/reference/generated-files.md)).
- **Breaking:** `__Projection<N>` schemas get stable names built from the type's shape. Add a named type alias to choose one.
- **Breaking:** install `@exprtlabs/golem` at or above the version the SDK was generated for, with the same major version. Generation commands fail before writing when it is older.
- **Breaking:** codec ids in generated files change. A hand-written model and an SDK model with the same name and shape no longer share an id.
- **Breaking:** the output inventory (`.golem/outputs.json`) records a `destination` and `destinationKind` for every file.
- Golem sorts names, keys and imports in generated files, `.golem/outputs.json` and `.golem/codec-keys.json` by code unit, so the same sources give byte-identical files under any machine locale. Regenerate once: an order that followed your locale (such as `maximum` before `maxLength`) changes. Field order feeds the codec id, so regenerating changes codec ids and SDK `_group-<hash>` file names once. For example, the fields `eTag` and `email` swap places.

- `@exprtlabs/golem/validation`: `getModelValidator` (use `getValidator(model)`), `findCachedModelValidator`, `cacheModelValidator`, `validateGeneratedValue`, `preflightModelValidation`, `formatGeneratedIssues`, `evaluateModel`, `validationTagKey`, `validationTagSchemaDescriptor` and `validationTagGroups` (the first two tag helpers moved to `@exprtlabs/golem/schema`), and the structural validation helpers `fail`, `pushPath`, `popPath`, `enterActive`, `leaveActive`, `readOwn`, `runTag`, `runNestedModel`, `withNestedScope`, `childPath`, `continueStep`, `getProjection`, `rememberProjection`, `projectNestedModel`, `missingValidation` and `ensureNestedReady`. The `ModelValidator` constructor takes only the model.

- `@exprtlabs/golem/errors`: `errorOwnerChain`, `invocationOwners`, `attachErrorOwners` and `readErrorOwners`.
- `@exprtlabs/golem/serde`: `bindCodecIdToConstructor`, `lookupOperationCodec` and `PUBLIC_SERDE_CALLS` (the call table now lives with the docs).

- `@exprtlabs/golem/schema`: `constraintSchema`. `@exprtlabs/golem/schema-graph`: `jsonSchemaBundle` and `codecDeclarationKey`. Both entries are build-time tooling for the generators.
- `@exprtlabs/golem/type-analysis`: `isIModelReference` (use `isModelDeclarationReference(checker, node)`). `@exprtlabs/golem/ts`: `readConfigFile`, `parseConfigFileTextToJson`, `flattenDiagnosticMessageText`, `createSourceFile`, `createProgram` (use `createProgramFromSources`) and the `errors` result of `parseJsonConfigFileContent`. `@exprtlabs/golem/emitter`: `generatedVariant` and `pruneNamedImport`.
