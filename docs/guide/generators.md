# Write a generator

The key `payment-events` is the block that the package registers. Its keys are the package's own: `output` is the directory that the generator owns, and `events` is an option that the plan entry reads. Golem runs the job before the models job, because the job reads no TypeScript program and the models job does, so the models job reads the files that the generator writes ([job order](/reference/config#job-order)).

## Register the block

The `golem` field in the `package.json` of the package sets four things: `apiVersion` (`2`), the `block` name (`payment-events` here), and the `plan` and `generator` entries.

- `plan` exports `plan`. It reads the block, checks it, and declares the job: the `output` folder that the job owns. It loads no TypeScript.
- `generator` exports `apiVersion` and `generate(context)`. It runs the job.
- Both subpaths are keys of `exports` in the same `package.json`. The example exports both from one file.

The field, the plan entry and the facts of a job are in [Register a block](/reference/generator-api#register-a-block).

## Write the generator

The generator module exports `apiVersion` and `generate(context)`:

<<< ../../examples/payments/generators/event-models.js#event-generator

- `apiVersion` is `1`. The CLI rejects a generator that reports another version.
- `context` holds the `options` that your plan entry returned for the job, and `onInput`. In this example the options are the absolute `output` directory, the `events` and the `profile`.
- `generate` returns the files as `artifacts` with absolute paths. It does not write them. Golem does.
- Each artifact starts with `/* Generated by <package>. Do not edit. */`, with your package name. A space, a line end or a full stop must follow the package name. Without it, golem refuses the file.
- Throw an error, or return diagnostics with severity `error`, to stop generation with a message.

Your code imports from golem only through `@exprtlabs/golem/generator-api` ([extension API](/reference/generator-api#generator-api)) and the plan helpers. It offers helpers such as `stableJson`, `compareText` and `resolveProfile`.

The generator writes source models. The models job makes their codecs. Your package version does not need to match the version of golem.

## Announce inputs

`manifestPaths` and `watchInputs` list the manifests and input files that the generator reads. This generator reads only its options, so both are empty.

Golem skips a generator whose inputs did not change. It learns an input when the generator calls `context.onInput(path)` before it reads the file. Golem also records a file in `watchInputs` that the generator did not announce, but it reads that file when the generator returns. If the file changed during the run, the next run runs the generator again. A directory that the generator did not announce makes the generator run every time. Call `context.onInput(path)` for each file you read, so golem records it at the read.

## Check what it writes

The generator writes `payment-events.model.ts` into the `output` directory. The models job then writes `payment-events.model.generated.ts` beside it. Both are generated files. Ignore or commit them with the others ([ignore or commit generated files](/reference/generated-files#gitignore)). The `.gitignore` of the example lists the first file by path.

## Publish and install

In your own project, publish the generator as a package and install it:

```sh
npm install --save-dev your-generator-package
```

The example project registers the block in its own `package.json`, so it runs without an install.

Full example: [`examples/payments`](https://github.com/RunicCore/golem/tree/master/examples/payments).
