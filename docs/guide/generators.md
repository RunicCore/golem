# Write a generator

Write a generator package that emits source files, and let `golem generate` run it before the model job.

## Configure the job

<<< ../../examples/payments/server/golem.yaml#generator-job

Each `generators` entry names an installed package, an `output` directory that the generator owns, and `options` that golem passes through untouched ([generator jobs](/reference/config#generator-jobs)). Generator jobs run before the built-in jobs, so the [models job](/reference/config#typescript-models) reads the files that a generator writes.

## Write the generator

The package exports `./generator`. That module exports `apiVersion` and `generate(context)`:

<<< ../../examples/payments/generators/event-models.js#event-generator

- `apiVersion` is `1`. The CLI rejects a generator that reports another version.
- `context` holds the absolute `directory` of `golem.yaml`, the absolute `output` directory, your `options`, the `profile` and `onInput` ([`GeneratorJobContext`](/reference/generator-api)).
- `generate` returns the files as `artifacts` with absolute paths. It does not write them. Golem does.
- Each artifact starts with `/* Generated by <package>. Do not edit. */`, with your package name. A space, a line end or a full stop must follow the package name. Without it, golem refuses the file.
- Throw an error, or return diagnostics with severity `error`, to stop generation with a message.

Your package version does not need to match the version of golem.

## Announce inputs

`manifestPaths` and `watchInputs` list the manifests and input files that the generator reads. This generator reads only its options, so both are empty.

Golem skips a generator whose inputs did not change. It learns an input when the generator calls `context.onInput(path)` before it reads the file. Golem also records a path in `watchInputs` that the generator did not announce, but it reads that file when the generator returns. A change to the file during the run can go unseen, so call `context.onInput(path)` for each file you read.

## Check what it writes

The generator writes `payment-events.model.ts` into the `output` directory. The models job then writes `payment-events.model.generated.ts` beside it. Both are generated files. Ignore them with the others ([ignore generated files](/reference/generated-files#gitignore)). The `.gitignore` of the example lists the first file by path.

## Publish and install

In your own project, publish the generator as a package and install it:

```sh
npm install --save-dev your-generator-package
```

The example project exports `./generator` from its own `package.json`, so it runs without an install.

Full example: [`examples/payments`](https://github.com/RunicCore/golem/tree/master/examples/payments)
